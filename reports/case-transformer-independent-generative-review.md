# 共享生成案例：独立数学与代码复核

## 结论

对 `content/vla.json` 的 Diffusion 完整代码、`content/generative.json` 的 `score-sde` 完整代码与 `shared-mixture` 小节，以及 `content/figures/generative-shared-paths.svg` 进行只读复核。未发现需要阻止合并的数学或实现问题；没有修改这些文件。

此复核没有重新训练 DDPM 网络。主代理已运行训练；本复核负责核查反向均值、方差、条件混合 Oracle、时间方向与解析 PDE，并额外执行跨时间点验证。

## 时间方向与 VP 日程

正文以生成时钟 r 从噪声走向数据，取 α=sin(πr/2)、σ=cos(πr/2)。转换到前向时钟 τ=1−r 后，信号系数为 cos(πτ/2)，因此 β(τ)=−2∂τ log α=π tan(πτ/2)=πσ/α。前向概率流速度为 −β(x+score)/2，生成时钟的速度是其负值，即 +β(x+score)/2。

代码用这一正号验证生成速度，并将 −∂r p 与前向 Fokker–Planck 算子比较，方向与 1/2 系数正确。正文也明确 β 在 τ→1 发散，标准 Gaussian 端点是边际极限；并未将 β(1) 代入有限步 SDE。DDPM 的有限离散日程与用于对照的正弦/余弦连续路径已经分开。

额外检查 r=0 的直接条件均值公式，得到有限的生成速度 `(π/2) E[Y|c]`。这不等于可以把奇异的 β 表达式直接代入端点：β 和 x+score 的乘积必须取极限，或采用代码中不含该除法的条件均值表达式。

## 混合责任、条件均值与 Score

每个分量的中间均值为 αμ，协方差为 qI，其中 q=α²s_d²+σ²。所有分量共享 q，因此责任权重中可消掉共同 Gaussian 常数；代码计算真实 log p 时保留 `−D/2 log(2πq)`，没有漏掉密度的时间依赖。

Score 等于责任加权的 `−(x−αμ)/q`。由联合 Gaussian 条件均值得到的 clean_mean 与 noise_mean 均正确，并满足 `α clean_mean + σ noise_mean = x`。`noise_mean=−σ score` 与 `clean_mean=(x+σ² score)/α` 仅在相应除法有效时使用。速度由系数导数加权这些条件均值，确实是边缘速度，而非一次训练配对的隐藏端点速度。

Diffusion 的 `oracle_noise` 正确处理 `[B,1]` 系数与 `[B,2,2]` 残差的广播，并用后验责任平均噪声条件均值。固定探针上的模型误差与 Oracle 误差没有被错误宣称可以逐点精确相加。

## DDPM 与方法比较

DDPM 采用零起始数组索引：第0项是第一次加噪状态，干净数据独立命名。反向均值使用标准噪声参数化，posterior_variance 的前一累计信号系数以1补齐，第0步不加新噪声。终端累计 α 非零与有限 Gaussian 反向步的近似都已在正文/运行结果中说明。

DDPM 的采样噪声标签、线性 FM 的 Y−Z 与 VP 条件速度具有不同的目标尺度、时间加权和不可约回归误差。即使共享数据与条件，也不能按原始 MSE 排序生成算法。当前代码说明和前置的参数化损失权重推导已覆盖这一限制；`shared-mixture` 本身只验证解析恒等式，未把两种目标训练损失拼成性能排行榜。

## 额外执行的检查

在独立四点输入与两个条件上，分别对线性/VP 路径检查 r=0.05、0.2、0.4、0.75、0.95，共10组设置：

- 解析 Score 与 `Autograd(log p)` 一致，最大绝对误差约 `6.76e−14`。
- clean/noise 条件均值重新组合为原 x。
- 生成时钟连续性方程成立，最大绝对误差约 `5.00e−16`。
- VP 的 `−∂r p` 与前向 FP 一致，最大绝对误差约 `6.67e−16`。
- VP 生成速度的正号及噪声端点直接条件均值表达式通过检查。

精确源码 SHA、逐设置误差记录见 `case-transformer-independent-generative-review.json`。这些有限点检查结合以上代数核对构成验证证据，不是对所有浮点输入稳定性的证明。
