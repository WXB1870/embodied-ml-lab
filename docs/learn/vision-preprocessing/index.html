视觉模型的输入并非抽象的图像，而是经过解码、重采样和数值变换的张量。相同尺寸的张量可能对应不同颜色、像素中心或物理位置，这些差异会沿编码器传递到策略。本章从像素与坐标的定义建立预处理链，推导缩放、裁剪和补边怎样同步作用于图像与标注，再用可辨认的人工输入检验训练和部署是否采用了同一套视觉约定。

前置知识：张量与广播 · CNN：卷积、采样与空间表示

01像素布局与数值含义

神经网络接收数值，却无法推断这些数值原来表示哪种颜色或量纲。先明确像素的布局与范围，可以把“图像看起来正常”转化为能逐项核对的输入约定。

相同 [H,W,3] 数组可以表示 RGB，也可以表示 BGR；相同 float32 张量可以处于 [0,255]、[0,1] 或标准化后的范围。模型看到的是数字，不知道读取库做过什么。明确输入颜色空间、布局、dtype、范围以及无效值策略，才能判断一次除法、通道交换或归一化是否合理。

预训练视觉编码器的处理器属于模型接口：尺寸、裁剪方式、插值、抗锯齿、均值和标准差都应与 checkpoint 配套保存。教学示例约定 uint8 RGB，转换为 CHW，再除以 255 并映射到 [-1,1]；这不是所有视觉模型的通用默认值，也不能据此覆盖现成处理器。

例如，OpenAI 发布的 CLIP 在 clip.load 中同时返回模型和配套预处理：先用双三次插值缩放，再中心裁剪、转 RGB，最后按其通道统计量标准化。中心裁剪可能移除画面边缘，不能与本章保留画布的 Letterbox 混为一谈。接入空间预测任务时，应根据实际处理链同步更新标注；更换裁剪方式则属于输入分布的改变，需要重新验证。具体实现见CLIP 官方处理器。

常见双重处理是 Dataset 已 rescale，模型 processor 又 rescale 一次。它不会报 shape 错误，但会把动态范围压缩数百倍。最有效的检查不是只看最终 min/max，而是在解码、变换、归一化三个边界记录数值统计，并用通道不对称的人工图案观察每一步。

例：一个红像素如何暴露重复归一化

  1. uint8 RGB 红像素为 [255,0,0]，除以 255 得 [1,0,0]。
  2. 使用 mean=std=0.5 逐通道标准化后得到 [1,-1,-1]。如果读取成 BGR，亮通道会落在第三维。
  3. 一个原本为 0.5 的浮点通道若又除以 255，再做上述标准化，会从正确的 0 变成约 -0.996。

dtype 是存储类型，数值范围是约定；必须分开验证。

用 float32 推断图像已经位于零到一

转换 dtype 只改变表示格式，不会改变物理范围。重复 rescale 仍会输出有限张量，因此梯度和 shape 检查常发现不了。

检查：输入纯红、纯绿和中灰图，核对每通道预期值；记录 processor 是否已经执行 rescale/normalize。

02换轴、插值与抗锯齿

改变布局只重新安排索引，改变尺寸则要重新估计采样位置上的值。区分这两类运算后，才能理解插值、抗锯齿和坐标对齐各自解决的问题，以及为什么图像与离散标签不能总用同一处理。

HWC 转 CHW 是轴置换，应使用 permute(2,0,1)，不能用 reshape(3,H,W) 重排解释内存。reshape 保留元素线性次序，可能把相邻像素误当成不同通道。送入 F.interpolate 前还需增加 Batch 轴，输入形状为 [1,C,H,W]；size=(height,width)，不能直接沿用其他图像库常见的宽高顺序。

双线性插值把周围采样值加权用于连续图像；分割类别 ID 不是连续量，把类别 0 和 2 插成 1 会制造不存在的类别，应使用合适的最近邻规则。深度、有效位与稀疏关键点也不能无差别套用 RGB 的插值方式，尤其应避免无效深度参与普通平均。

缩小图像时，高频纹理可能混叠为伪纹理，antialias 处理可减轻这种问题。它与 align_corners 是不同开关：前者涉及重采样滤波，后者涉及坐标对齐。参数不一致可能让训练与部署输入略有不同；比较两条处理链时应直接核对输出像素，而不是仅检查最终尺寸。

03拉伸、裁剪与 Letterbox

输入尺寸固定时，原始图像的比例和内容不可能总被原样保留。拉伸、裁剪与补边对几何信息作出不同取舍；先理解这种取舍，再记录实际缩放和偏移，才能恢复预测位置。

直接 resize 到目标宽高最简单，但会改变物体纵横比；保持比例后裁剪可以填满画布，却会删除边缘内容；Letterbox 保持主要比例并补边，但有效图像占比会变化。没有一种变换对所有模型都最好，应先满足预训练接口，再根据任务的可见性与标签约定选择。

Letterbox 先取 r=min⁡ ⁣(HoutHin,WoutWin)r=\min\!\left(\frac{H_{\mathrm{out}}}{H_{\mathrm{in}}},\frac{W_{\mathrm{out}}}{W_{\mathrm{in}}}\right)r=min(Hin​Hout​​,Win​Wout​​)⁠，再把缩放后的高宽取整。由于整数舍入，实际 sx=new_widthold_widths_x=\frac{\mathrm{new\_width}}{\mathrm{old\_width}}sx​=old_widthnew_width​ 与 sy=new_heightold_heights_y=\frac{\mathrm{new\_height}}{\mathrm{old\_height}}sy​=old_heightnew_height​ 可能略有不同。关键点计算必须使用实际尺寸对应的比例，不能把理想 r 当成两个轴完全相同的精确比例。

居中补边也可能左右或上下相差一个像素：总缺口为奇数时，floor 得到的前侧补边与后侧不同。元数据应保存实际新尺寸、left/top/right/bottom 及变换矩阵。若只存“resize 到 224”这类模糊说明，之后很难把预测映射回原图并诊断系统偏移。

04像素中心与半像素项

几何变换不仅取决于缩放比例，还取决于坐标原点放在像素中心还是像素边界。半像素项正来自两种坐标描述之间的转换，应从定义推导，而不是作为经验补偿加入。

本节把整数 u、v 解释为像素中心，图像边界因此位于 -0.5 与 W−0.5W-0.5W−0.5⁠。align_corners=False 的常见缩放约定保持像素区域边界一致：先将中心坐标加 0.5 转成相对边界的位置，乘实际比例，再减 0.5 回到中心坐标，最后加补边。这解释了公式中的半像素项。

若坐标采用连续图像边界为零、或另一个 API 用角点中心对齐，就必须换用相应映射；半像素项不是所有关键点系统必加的修正。align_corners=True 在非退化尺寸下对应角点中心之间的比例，不能只改变插值参数而继续使用另一套标注公式。

齐次矩阵 A 把缩放和平移统一起来。点的正向变换用 A，反变换用 A 的逆；多个几何变换按执行顺序相乘，注意列向量与行向量约定。正反变换一致是必要检查，但若两边共享同一个错误约定，仍可能都通过，因此还需要明确已知位置的人工图案。

横纵实际比例和不对称补边都参与映射；最终点不必落在画布的几何中心。

几何增强返回元数据和有效性

单独返回变换后的图像，无法可靠恢复点、框或相机几何。对于被裁掉的目标，还必须判断监督是否仍然可见。

检查：保存 A 和原始/实际新尺寸；核对几个已知角点、中心点及逆变换，并显示点在新图中的位置。

05图像、相机与物理坐标

图像上的位置变化与真实场景中的物体运动属于不同空间。把像素变换接到相机投影模型上，可以推导哪些二维标注和内参需要同步改变，哪些三维量应保持不变。

二维关键点随图像几何变换；矩形框通常需要变换其角点，再按任务约定裁剪到图像范围，并同步更新可见位。分割掩码必须与图像共享同一组随机几何参数，却采用适合离散标签的插值。对图像和标签各自调用一次随机裁剪，即使使用同一种变换类，也可能抽到不同裁剪。

相机投影满足齐次关系 p∼KXcamerap\sim KX_{\mathrm{camera}}p∼KXcamera​⁠。若对投影像素施加仿射 A，则新的像素投影为 p′∼AKXcamerap^{\prime}\sim AKX_{\mathrm{camera}}p′∼AKXcamera​⁠；在一致坐标约定下，可把对应变换合并到内参表示。实际标定、畸变校正与裁剪顺序还会影响接口，应保存完整流程，而不是只修改一个焦距数字。

图像裁掉左边十个像素，不会把世界坐标中的物体平移十米或十个像素。三维物理点、相机外参、二维投影有不同的坐标空间。几何图像增强可以改变观测可见性和投影关系，却不自动改变真实场景；物理旋转或更换相机才需要相应的三维坐标变换。

06补边、缺失视角与有效位

补边和缺失视角都会产生特殊数值，但特殊数值本身并不能告诉网络哪些信息无效。需要把像素取值与有效性分开建模，再沿编码、融合和池化检查无效输入如何被处理。

补零发生在归一化前后，含义不同。在 [0,1] 图像上补 0 是黑色，之后按 mean=std=0.5 标准化会得到 -1；在标准化张量上补 0 则对应原空间中灰。两者都可以作为明确设计，但不能训练用一种、部署用另一种；也不能直接将“零张量”解释为无信息。

一张缺失图像即使全零，视觉编码器仍可能通过偏置、位置编码和归一化输出非零 token。缺失视角应有显式有效位，并在融合和池化中按约定处理。若一个样本全部视角缺失，应选择报错、备用输入或定义好的空条件；把所有键遮成不可见后继续 softmax，可能产生无意义结果或 NaN。

部分 Letterbox 区域属于填充，是否为这些区域生成有效 token 取决于具体编码器接口。一个 patch 跨越图像与补边时也不是简单全有或全无；教学中可以说明保留整个画布，实际模型则应沿用其训练时约定。不能临时新增 token mask 后宣称与预训练处理完全等价。

SigLIP 2 的 NaFlex 变体展示了另一种明确设计：根据 Patch 大小和 Token 预算缩放图像，尽量保持原始纵横比，再输出 Patch 序列、空间坐标与补齐 Mask；注意力和汇聚也使用该 Mask。它与固定方形输入的标准变体具有不同的处理协议，并不是给任意 ViT 传入非方形图片即可等价实现。使用时应保留官方处理器产生的坐标和有效位，详见论文第 2.4.2 节与官方 NaFlex 预处理。

07多视角与多帧顺序

多个视角或时间片进入同一序列后，位置本身就承担来源身份。保持相机和时间顺序一致，才能让模型解释各个特征；随机增强也必须服从这种跨视角、跨时间的关系。

多相机输入要用固定名称表建立位置映射，再逐项读取当前可用图像；不能按字典当前迭代顺序直接 stack。否则少一台相机后，后续视角可能整体换位，位置或相机 embedding 的语义随之改变。明确相机名称、帧时间、外参和有效位，可以让这种错误在进入模型前就被检测。

多帧任务还需说明时间排序与帧间隔。将未来一帧误放到当前观测，可能让离线误差很好但部署无法复现；复用过期图像也不能仅因为 shape 一样就当成同步输入。时间戳、采样规则和缺帧策略应与其他状态输入的对齐规则一致。

增强是否在多个视角或时间步共享，要根据物理与监督目标决定。各帧独立亮度扰动与独立随机裁剪的影响不同；后者会引入额外的相对运动。若希望学习真实运动或跨视角几何，应记录并合理共享几何变换，不能把所有张量拉平成一个大 Batch 后盲目施加互不相关的增强。

用当前字典顺序或缺失黑图表达相机身份

输入顺序变化会把相同 token 位置绑定到不同相机；全零占位也不能阻止编码器产生特征，二者需要分别处理。

检查：打乱输入字典顺序并删除一个视角，确认固定名称表对应的槽位不变，有效位变化，融合结果不依赖无效占位内容。

08预处理与标签的几何对照

坐标往返一致只能证明两段代码相互匹配，不能排除它们共享同一个错误约定。用已知通道、尺寸和关键点的人工输入作为独立参照，才能把预处理的语义正确性一并检验。

先用确定性人工输入检查约定：三通道不同常数检验颜色；非方形尺寸检验宽高顺序；棋盘或线条检验缩放；已知关键点检验位置；缺失相机检验有效位。仅凭自然图像的视觉检查，可能遗漏半像素偏差、轻微错位和轴顺序错误。

接着在同一原始输入上对比训练与推理处理链的最终张量和元数据。允许的差异应能解释，例如训练专用随机增强；验证与部署路径应尽可能确定。保存处理器配置到 checkpoint，避免权重恢复后无意中使用另一套均值、分辨率或裁剪方式。

示例接口采用 uint8 RGB、双线性 Letterbox、像素中心关键点和显式视角有效位。畸变校正、相机标定或其他骨干所需的颜色与插值配置，应在相应处理器中单独对齐。
