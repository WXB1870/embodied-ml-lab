为什么图像正确 resize 后，关键点直接乘同一个理想 ratio 仍可能不对？本节为什么还有 0.5？

参考解与分析

输出尺寸必须取整数，实际 sx=nwws_x=\frac{\mathrm{nw}}wsx​=wnw​ 与 sy=nhhs_y=\frac{\mathrm{nh}}hsy​=hnh​ 可能略有差别，还要加上 Letterbox 的 left、top。只乘舍入前 ratio 会遗漏真实比例和补边。

本节把整数点解释为像素中心，并配合 align_corners=False。映射采用 (u+0.5)sx−0.5+left(u+0.5)s_x-0.5+\mathrm{left}(u+0.5)sx​−0.5+left⁠；使用边界坐标或不同插值对齐规则时必须重新确定公式，不能把半像素项当作所有坐标系统的固定常数。

代码对应：检查实际 resized.shape、sx/sy、补边宽度和关键点正反变换。

  • 说明整数尺寸、横纵实际比例和补边三项。
  • 把半像素项与明确的坐标约定联系起来。

某个相机视角缺失时，补一张黑图是否足够？若对图像做裁剪，物理三维位置标签是否也要平移同样的像素数？

参考解与分析

黑图只是占位内容，还要有显式有效位，并让后续融合忽略缺失视角。相机顺序应由固定名称表定义，避免缺一个键后其余视角的索引整体变化。

像素裁剪改变图像坐标和可见性，不会把真实场景中的物理三维位置按像素数平移。二维关键点、相机内参与物理三维标签具有不同含义，需要分别处理；目标被裁掉时还应重新判断监督是否可由当前观测支持。

代码对应：跟踪 names、valid、每个视角的仿射元数据，以及标签的坐标系定义。

  • 同时提出占位与有效位，保持相机名称映射。
  • 正确区分像素变换与物理三维坐标变换。

计算 Letterbox 后的关键点

实现 map_letterbox_point(point,original_hw,target_hw)。使用正数四舍五入 int(value+0.5) 确定缩放尺寸，居中补边，像素中心约定与 align_corners=False 对齐。返回 (u',v')。

参考实现与说明

核对思路后，试着收起答案、恢复题目并独立重写；通过测试只表示满足本题提供的检查。

参考实现
def map_letterbox_point(point, original_hw, target_hw):    h, w = original_hw    oh, ow = target_hw    if min(h,w,oh,ow) <= 0:        raise ValueError("尺寸必须为正")    ratio = min(oh/h, ow/w)    nh, nw = max(1,int(h*ratio+0.5)), max(1,int(w*ratio+0.5))    top, left = (oh-nh)//2, (ow-nw)//2    u, v = point    return ((u+0.5)*(nw/w)-0.5+left,            (v+0.5)*(nh/h)-0.5+top)

在 5×9 到 12×12 的例子中，实际缩放为 7×12，横纵比例略不同。使用真实尺寸和半像素约定才能与图像处理链一致。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

用 reshape 替代 HWC 到 CHW 的 permute

reshape 不交换轴语义，可能把连续像素解释成颜色通道。用红绿蓝分离的人工输入检查各输出通道。

理想缩放比例直接用于所有标注

整数尺寸舍入使 sx 与 sy 可能不同，补边又引入平移。基于实际 resize 结果构造 A，并核对已知点。

对分割类别使用双线性插值

类别 ID 之间的数值平均没有类别意义。图像和掩码共享几何参数，但掩码需要离散标签适用的插值。

以为黑图不会影响融合

偏置和位置编码能把黑图转为非零特征。传递有效位，改变无效占位内容时有效输出应保持一致。

训练与部署各自实现一套处理

均值、补边空间、插值或颜色顺序的细小差异可能形成系统偏差。随 checkpoint 保存处理约定，并对相同原始输入逐项对照。
