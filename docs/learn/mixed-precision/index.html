低精度计算能够减少部分存储和运算成本，但它也改变了哪些数值差异能够被表示。混合精度需要在计算收益与误差之间设置清楚的边界，而非把模型整体转换为一种较小的数据类型。本章从浮点格式解释舍入、下溢与溢出，再推导损失缩放及其与累积、裁剪的顺序关系。每项机制都与 FP32 参照联系起来，用于判断误差来自前向、反向还是实际参数更新。

前置知识：数值精度与标准化 · 梯度累积

01范围与精度分别由指数和尾数控制

降低浮点位数并不是均匀地降低所有数值的精度，位数如何分给指数和有效数字决定了不同误差。先看具体格式可表示的范围和间距，才能解释为什么 BF16 与 FP16 会在不同位置失效。

浮点格式包含符号、指数和有效数字。指数决定数量级范围，有效数字决定相邻可表示值之间的距离。FP16 最大有限值为 65504；BF16 与 FP32 的指数范围相近，但有效数字明显更少。因此 BF16 缓解了不少范围问题，却不等于有 FP32 的局部精度。

在 [1,2) 区间，BF16 相邻可表示数的间距为 2−7=0.00781252^{-7}=0.00781252−7=0.0078125⁠，FP16 为 2−102^{-10}2−10⁠，FP32 为 2−232^{-23}2−23⁠；可以用 torch.finfo(dtype).eps 核对。间距会随数的量级改变，这不是所有数都具有同一绝对误差界。1.001 转成 BF16 会被舍入成 1，之后再转回 FP32 仍是 1。

下溢、溢出与舍入需要分开处理。梯度缩放可使某些小梯度在反向中落到更易表示的范围，但不能找回前向已经舍掉的残差，也不能修复先前产生的 Inf。若参数本身以低精度存储，过小的更新还可能被加法舍入吞掉；保留 FP32 参数和合适精度的优化器状态，解决的是另一段计算路径。

autocast 选择哪些算子使用低精度，收益取决于设备、内核、形状和数据传输。dtype 打印可以核对计算边界，实际精度、速度和显存则要在目标环境测量。

02autocast 按算子选择 dtype，不等于 model.half

不同算子对范围与精度的需求不同，整张网络没有必要统一使用同一种计算类型。autocast 提供按算子划定的边界，而参数存储与优化器状态仍需单独理解，不能由一个输出 dtype 推断全部过程。

autocast 在上下文中依据算子规则选择计算精度；某些矩阵乘法可以用低精度，某些敏感操作会保持或提升精度。模型参数可以继续以 FP32 保存，反向梯度与优化器状态也有各自的 dtype。手动将整个模型 half 会改变参数存储和更多运算，不能把它当作 autocast 的同义写法。

推荐的基础模式是在 autocast 中执行前向和 loss 计算，再在外部反向。不要为追求统一而反复手动 cast 中间张量，否则可能破坏算子策略或引入额外拷贝。自定义算子、未覆盖的操作和跨上下文输入需要检查实际 dtype；某个张量显示 float32，也不代表前面的所有乘加都使用了 FP32 精度。

查看关键算子的输入、输出和参数 dtype

混合精度是计算路径的配置，不能只检查模型权重一个 dtype。

检查：在最小例子中打印线性层输出、loss、参数与梯度 dtype，核对实际精度边界。

03梯度缩放为何能保护小梯度

反向链条中的很小数值可能在低精度中消失，即使最终需要的梯度仍有意义。利用求导对常数缩放的线性性，可以临时放大这条链条，再在更新前还原；这一推导也明确了它无法修复的前向问题。

设原损失为 L，乘上正缩放因子 s 后，反向得到 s∇Ls\nabla Ls∇L⁠；若在更新前除以 s，数学目标保持不变。放大后的梯度可能落入低精度更容易表示的范围，减轻下溢。缩放因子太大又会导致梯度溢出，因此动态缩放器会根据有限性检查调整。这个机制保护的是数值表示，不会增强模型的信息或改变正确目标。

缩放不能修复前向阶段已经产生的 NaN/Inf。比如输入过大使矩阵乘法先溢出，或者 log 接收非法值，后续无论怎样缩放 loss 都无法恢复正确中间结果。BF16 常因指数范围较宽而不需要与 FP16 相同的缩放策略，但也不能据此宣称任何 BF16 模型都不会出现非有限值。

例：缩放与还原的数值含义

  1. 原始梯度假设为 10−810^{-8}10−8⁠，缩放因子 s=216=65536s=2^{16}=65536s=216=65536⁠。
  2. 缩放后梯度约为 6.55×10−46.55\times10^{-4}6.55×10−4⁠，落到更容易表示的量级。
  3. 优化前除以 65536 才回到原本梯度；若忘记还原，相当于大幅改变更新尺度。

正确缩放不应改变优化问题，只改变中间数值的表示范围。

04unscale、裁剪与 step 的正确顺序

缩放后的梯度与原目标梯度具有不同数值单位，任何依赖绝对范数的操作都必须使用正确单位。由此可以推出还原、裁剪和更新的顺序，而不是只记住一段固定的 AMP 模板。

如果在缩放梯度上按原阈值裁剪，就相当于把真实梯度阈值缩小了 s 倍。应先完成反向，再 scaler.unscale_(optimizer)，然后对真实梯度裁剪，再 scaler.step 和 scaler.update。一次更新中对同一 optimizer 只应 unscale 一次；多个优化器则要明确每个参数由哪个优化器管理。

scaler.step 会检查其管理的梯度是否存在非有限值，并可能跳过实际 optimizer.step。日志中看到调用过 scaler.step，不足以证明参数发生更新。应记录跳步事件、缩放因子与真实参数位移；按更新步设计的学习率日程也要协调。连续跳步通常值得排查前向尺度或梯度异常，不能把“没有崩溃”当作有效学习。

例：在缩放梯度上裁剪的后果

  1. 真实梯度范数为 2，缩放因子为 1024，看到的范数为 2048。
  2. 若直接裁剪到 1，再除以 1024，真实梯度只剩 11024\frac1{1024}10241​⁠。
  3. 先还原成范数 2，再裁剪到 1，才是原先设定的阈值。

裁剪阈值有单位，必须与梯度所处的缩放状态一致。

在 unscale 之前按真实阈值裁剪

这会严重削弱梯度，甚至让训练看似稳定但几乎不更新。

检查：记录还原前后范数，确认裁剪使用的是实际梯度尺度。

05累积和多任务不能混入不同缩放单位

多个微批次或损失共同作用于同一参数时，缩放单位还必须在贡献之间保持一致。额外调用 autograd.grad 返回的张量也可能绕开优化器的还原流程，需要沿每一条梯度路径核对。

一个有效批次内累积的所有梯度需要使用相同缩放因子。中途 unscale 或 update 会使 .grad 混合不同比例，无法再通过一次除法恢复。应在完整累积后才执行有限性检查、还原、裁剪和更新。同样，若多个损失共同训练一组参数，它们的相对权重应先按目标定义好，再按一致规则缩放。

autograd.grad 返回的梯度不一定存放在 optimizer 管理的 .grad 内，scaler.unscale_(optimizer) 不会自动处理这些返回值。做梯度惩罚或梯度范数诊断时，应明确返回的是缩放梯度还是原梯度，并按所需数学目标自行还原。误把缩放后的诊断值解释为真实任务强度，会导致权重判断失真。

排查这种组合问题时，先在 FP32、单任务、无累积条件下建立正确参照，再逐项开启低精度、累积和梯度诊断。一次启用全部机制时，即使最终 loss 变化，也难以确定是哪一处改变了计算含义。

06敏感运算可以局部使用更高精度

当误差集中在少量敏感算子时，可以只提高这些边界的计算精度。关键在于精度提升必须发生在信息丢失之前；转回更宽的格式不能恢复已经被低精度舍去的差值。

平方误差的残差、均值方差、概率归一化或很长序列的加和，可能对精度更敏感。可以在明确边界把相关输入转为 FP32，使用稳定公式计算，再继续后续路径。局部提升应依据对照结果，而不是对整个模型无差别禁用低精度。需要注意 cast 的位置：若低精度残差已经舍入为零，再转 float 不会恢复丢失的差异。

类似地，低精度前向输出即使随后做 FP32 loss，也仍带有前面算子的舍入误差；这通常是混合精度设计的一部分，但必须评估是否可接受。比较模型时可同时检查 loss、若干激活、逐参数梯度与一次更新，找出误差首次显著增长的位置。单独要求所有元素逐位等于 FP32 不现实，单独要求“最终有限”又太弱。

两条路径最终都用 FP32 相减，但第二条的两个输入已经先被 BF16 舍入为同一个数，所以残差为零。若要保留这段差异，必须在信息丢失前保留更高精度；仅把最终 loss 转成 float 或增大 GradScaler 倍数都无法恢复它。

检查：把精度提升放在敏感运算之前，并对照提升前后的中间值及梯度。

07如何区分前向溢出、反向下溢与真实优化问题

非有限输出、极小梯度和参数不动是不同现象，可能发生在不同计算阶段。固定输入和状态后逐段比较 FP32 与低精度路径，可以找到首次分歧，并据此选择公式、尺度或精度上的修复。

前向出现 Inf/NaN 时，先检查输入、预激活、归约和 loss；loss 有限而梯度非有限时，重点检查局部导数、缩放倍数和不稳定反向算子；梯度有限却参数不动时，再检查优化器、跳步、学习率和更新是否小于参数可表示间距。不同现象应对应不同实验，不能一概归结为显卡精度不够。

对照实验固定相同权重、样本和随机因素，分别执行 FP32 与混合精度路径。若 FP32 也失败，应优先修复数学与管线；若只有混合精度失败，逐层定位首次分歧，检查范围与算子策略。记录每次修改的证据，如恢复有限梯度、降低相对误差或改善实际更新，而不是只记录“换 BF16 后好了”。

对梯度极小但有限的情况，还需比较优化前后参数是否真的改变。仅检查 isfinite 不会发现更新在参数存储精度下被舍入掉；参数差与预期更新量对照能够补上这个盲区。

08验证范围、性能测量与保存恢复

数值对照通过只是采用混合精度的一个条件，还需要在目标硬件上确认资源收益。保存精度配置与缩放器状态则保证后续恢复沿用同一计算协议，避免将不同数值路径误认为相同实验。

配套代码提供可执行的 CPU BF16 autocast 教学路径和清楚的 CUDA FP16 分支。CPU 检查能验证代码结构、dtype 与梯度关系，但不能证明某张 GPU 的吞吐、内核支持或数值表现。硬件性能应在目标环境固定批次形状、进行预热和同步计时，同时测峰值内存与有效样本吞吐。

保存训练状态时，除了权重与优化器，还要保存启用的 GradScaler 状态，避免恢复后无说明地改变尺度历史。记录 autocast dtype、关键精度例外和 loss 的归约方式。改变这些设置之后，重新检查固定样本的一步更新与独立验证表现；“同样的权重文件”不意味着所有数值路径都保持不变。

混合精度成功的证据是目标模型在可接受误差和任务指标下获得实际资源收益。训练不稳定、频繁跳步或额外 cast 开销过大时，应先定位瓶颈与数值问题，再决定在哪些模块使用低精度。

性能对照应避免被首次内核初始化、编译或文件读取主导。固定预热次数、测量区间与同步方式，记录训练完整 step 而非只测一个矩阵乘法。只有模型指标与资源收益同时可接受时，才构成这项精度配置的实际收益。

为了把精度放回同一训练任务，可运行共同训练项目的 verify_cpu_amp 和 train_window(cpu_amp=True)。它从同一初值核对 FP32 与 CPU BF16 的输出 dtype，并比较 loss 与梯度，检查 FP32 参数与 loss 归约，并实际执行一次更新。程序打印的误差只是固定小模型的观察，断言不构成 BF16 的普遍误差界；CUDA FP16、GradScaler 溢出跳步与 GPU 延迟不在本次 CPU 验证范围内。
