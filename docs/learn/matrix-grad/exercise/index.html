为什么对向量输出传全 1 反向，只得到一个 VJP，而不是完整 Jacobian？

参考解与分析

全 1 将 Jacobian 的所有输出行相加，得到 J⊤1=∇x∑ifiJ^\top\mathbf1=\nabla_x\sum_i f_iJ⊤1=∇x​∑i​fi​⁠。很多不同的 J 都有相同的行和，因此这一结果无法恢复全部逐输出偏导。若目标是 mean，还必须把种子除以输出数。

例如 f(x)=[x−x]f(x)=\begin{bmatrix}x\\-x\end{bmatrix}f(x)=[x−x​] 的 Jacobian 为 [1−1]\begin{bmatrix}1\\-1\end{bmatrix}[1−1​]⁠，输出对 x 都有依赖，但全 1 的 VJP 是 0。只看这个零梯度，不能判定两条路径都断开；它们可能恰好抵消。

完整 Jacobian 可用不同基向量的 VJP/JVP 组织得到，或调用 torch.func.jacrev/jacfwd。普通标量损失训练只需要自己的上游种子；排查多任务抵消时则应分别查看各目标的梯度。

代码对应：原理中的 jvp/vjp 对照；练习中 G 的归约分母。

  • 能写出全 1 VJP 丢掉了哪些逐输出信息。
  • 能区分路径断开与多条非零路径相互抵消。

有限差分为什么需要合适的 ε\varepsilonε⁠，且最好避开 ReLU 的零点？

参考解与分析

中心差分近似 L(w+ε)−L(w−ε)2ε\frac{L(w+\varepsilon)-L(w-\varepsilon)}{2\varepsilon}2εL(w+ε)−L(w−ε)​⁠。ε\varepsilonε 太大时局部线性近似不准，太小时两个接近损失的相减会放大舍入误差，所以演示使用 float64 和小型问题。

ReLU 零点不可微，框架选择的次梯度约定不必等于跨过两侧计算的有限差分。应在光滑测试点核对自定义梯度，同时避免把有限差分当作大模型训练算法。

代码对应：演示 STEP 3 的参数副本、eps=1e-6 与双精度比较。

  • 能说明截断误差和舍入误差的两种极端。
  • 能解释不可微点不适合作为唯一梯度正确性证据。

参考实现与说明
参考实现
def mse_gradient(x, y, w, b):    n = len(x)    errors = [w * xi + b - yi for xi, yi in zip(x, y)]    dw = sum(e * xi for e, xi in zip(errors, x)) / n    db = sum(errors) / n    return dw, db

若把 loss 改成平方误差的 sum，梯度会是当前结果的样本数倍。检查代码中的归约后再比较学习率。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

手推只除 Batch，代码却平均全部元素

多输出 mean 会引入输出维度的因子。先写出逐元素目标，再统一手推、框架和测试的分母；不要直接通过改学习率掩盖差异。

只比较梯度范数

正负相反或元素置换的向量可以有相同范数。至少逐参数逐元素比较，并核对参数顺序；同时使用绝对与相对容差。

在 ReLU 零点强行要求中心差分一致

非光滑点没有唯一普通导数。换到远离拐点的确定性输入，或按所采用次梯度约定解释结果，避免将边界数学误认为实现错误。

把 backward 当成参数更新

backward 产生梯度，optimizer.step 才执行优化算法。分别检查 grad、优化器成员和 step 前后参数，才能确认完整训练路径。
