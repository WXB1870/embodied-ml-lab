推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

按 episode 切分后验证很好，换物品明显失败，是否说明评估代码错了？

参考解与分析

不一定。不同 episode 仍可能包含同一物品、同一摆位和同一采集会话，因此原验证测量的是这个分布内的新轨迹表现。若结论要涉及新物品，就需按物品身份保留独立测试组；新会话、新背景和新操作者也是不同泛化轴。

先检查划分元数据和重复/近重复记录，再明确每份测试集的目标。标准化和任何数据驱动预处理只能由训练部分拟合。若用测试失败样例做了补采或调参，就应把它转为开发数据，并保留新的最终测试集。

代码对应：episode_id/task_id 分组、train_episodes 与统计量拟合边界。

  • 区分 episode 隔离与对象/会话隔离。
  • 说明测试集进入迭代后的角色变化。

两个任务数据量是 10:1，把它们每条记录的权重都设成 0.5，能得到任务各 50% 吗？

参考解与分析

不能。采样器看到的是逐记录权重，一个任务有十倍记录就会积累十倍总权重。若任务目标概率为 pkp_kpk​⁠、记录数为 nkn_knk​⁠，应给每条记录 pk/nkp_k/n_kpk​/nk​⁠，使同任务的权重和等于 pkp_kpk​⁠。

还要说明记录单位是帧、窗口还是轨迹，以及采样是否放回。目标比例是期望，不保证每个 Batch 恰好一致。记录实际抽样任务频率，并在比较模型时控制总样本数和训练预算；没有数据的正概率任务应明确报错或重设目标。

代码对应：sample_weights 中 Counter、逐任务归一化及 WeightedRandomSampler 日志。

  • 能推导 pk/nkp_k/n_kpk​/nk​⁠。
  • 区分配置概率、实际采样频率和每批平衡。

将 RLDS 转成 LeRobotDataset v3 后，为什么不能仅凭文件边界决定训练/验证划分，也不能把每行 action 都计入监督？

参考解与分析

v3 的一个 Parquet 或视频文件可以包含多个 episode，episode 也依赖元数据中的范围定位。切分与构造时间窗口应先确认原始 episode/session/场景身份。只有预先证明文件分片与所需独立分组一致时，文件才可作为该划分的实现单位；文件格式转换本身不提供新的统计独立性。

RLDS 规范中的最后观测没有有效后续动作；字段存在不等于有效标签，is_last 与 is_terminal 也有不同含义。转换时应保留或重建对应有效位，并检查动作和观测的时间约定。Padding、末步和缺失字段应分别处理，不能用动作是否为零推断。

代码对应：对照数据样本的 episode 标识、窗口索引与 action_valid，检查跨 episode 的窗口及最后观测是否进入损失分母。

  • 区分文件分片、episode 与评估独立单位。
  • 说明 last、terminal 与有效动作监督的关系。

从任务目标比例算逐样本权重

实现 sample_weights(tasks, desired)。tasks 是记录的任务标签列表，desired 是总和为 1 的非负目标概率。返回每条记录的权重；缺失但有正目标概率的任务、未知标签或空数据要报错。

提示
  • 先用 Counter 统计每种任务有多少条记录。
  • 验证一个任务内所有记录的权重和，是否等于 desired 中的概率。
参考实现与说明
参考实现
import mathfrom collections import Counter def sample_weights(tasks, desired):    if not tasks or not desired:        raise ValueError('empty data or distribution')    if any(not math.isfinite(p) or p < 0 for p in desired.values()) or not math.isclose(sum(desired.values()),1.0):        raise ValueError('invalid distribution')    counts = Counter(tasks)    if any(t not in desired for t in counts):        raise ValueError('unknown task')    if any(p > 0 and counts[t] == 0 for t,p in desired.items()):        raise ValueError('positive probability without data')    return [desired[t]/counts[t] for t in tasks]

任务概率是该任务全部记录的权重之和。把 0.5 直接赋给每条 reach 记录，会让三条 reach 总权重达到 1.5，改变预期比例。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

先标准化全数据再划分训练测试

测试分布会参与统计拟合。先按正确组切分，所有学习型预处理仅 fit 训练集。

把任务概率直接作为每帧权重

总概率还会乘以任务的帧数。按 pk/nkp_k/n_kpk​/nk​ 分配，并检查实际采样直方图。

按零值或全局分位数直接删数据

合法停顿、稀有恢复与缺失记录可能混在一起。结合有效位、任务阶段和物理含义记录清洗规则。

把长轨迹的帧数当独立示教数

时序与窗口重叠会形成相关性。分别报告帧、轨迹、会话与场景覆盖，并据此选择评价单位。

测试集失败后补采又继续称它为独立测试

这些条件已经参与模型开发。将它们归入开发集，另外保留未使用的最终评价条件。
