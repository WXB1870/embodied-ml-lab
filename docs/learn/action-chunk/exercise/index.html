推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

模型使用“前后各两帧”的图像窗口预测当前动作，离线效果很好。为什么这个实现可能无法部署？

参考解与分析

当前决策只能使用已经获得的观测。前后窗口中的后两帧来自未来，训练时额外提供了执行尚未产生的信息。部署时等待这些帧会改变决策时刻和动作目标；不能仅把相同窗口索引复制到在线程序。

应先定义观测截止时刻和动作生效时刻，改为因果历史，或显式把预测目标对齐到等待后的时刻。用未来帧扰动检查：改动决策时刻之后的图像，不应改变该时刻本来可用的模型输入。窗口还需按 episode 隔离并在开头标记缺失历史。

代码对应：window_indices 的历史 range(t−history+1,t+1)；构造输入前的时间戳检查。

  • 识别未来观测泄漏。
  • 给出不使用未来信息的索引和测试方法。

预测 H=16H=16H=16 步、执行 K=4 步，推理延迟增加后，能否直接把 K 调大解决？

参考解与分析

K 调大通常能延长已有动作的播放时间，但也延长了再次获得反馈前的开放执行阶段。它改变反应能力、源观测年龄与重规划节奏，并不消除延迟。先测量端到端延迟分布、动作间隔、可用队列长度和实际消费速度。

新的 chunk 到达时，要根据观测时间戳对齐到未执行的未来槽位，丢弃已经过去的部分。若有效剩余时长仍不足以覆盖下一次推理，调整 K 本身不一定解决问题。比较方法时应固定动作语义并记录停止、过期与队列耗尽事件。

代码对应：code.source 的 execution_horizon 与部署层的时间戳/队列消费逻辑。

  • 区分 H、K、控制频率和推理延迟。
  • 说明更长执行窗口对反馈新鲜度的影响。

参考实现与说明
参考实现
def window_indices(length, t, history, horizon):    if min(length, history, horizon) <= 0 or not 0 <= t < length:        raise ValueError('invalid window configuration')    obs = [i if 0 <= i < length else None for i in range(t-history+1, t+1)]    act = [i if 0 <= i < length else None for i in range(t, t+horizon)]    return obs, act

这些索引依赖上述时间约定。接入真实数据集时，先验证图像和命令的记录顺序，再确定标签应该从 t 还是其他索引开始。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

历史窗口里使用未来插值

检查插值使用的右端样本是否在线可用。必要时改因果保持或明确引入等待时间，并保持训练部署一致。

只对输出 Mask，忽略输入 Padding

跨位置网络可能读取无效输入。用无效输入扰动检查有效输出，并明确注意力或循环状态的处理。

预测 1 秒就认为拥有 1 秒反应余量

返回时已过去的前缀不能再次执行。用槽位时间、端到端延迟与剩余有效时长判断队列预算。

重叠动作按相同索引平均

不同生成时刻的数组索引不对应同一控制时刻。先做时间与参考锚点对齐，再决定能否融合。

把生成迭代与物理执行频率绑定

采样器迭代更新动作分布，执行频率决定物理命令时间。分别配置并测量，不能用一个 steps 变量表达两者。
