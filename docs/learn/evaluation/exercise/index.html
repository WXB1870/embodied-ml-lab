推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

方法 A 是 9/10，方法 B 是 90/100，可以说两者证据同样充分吗？

参考解与分析

两者点估计都是 90%，但有限独立试验带来的不确定性不同。用相同方法计算区间时，一百次通常比十次更窄。应报告成功次数、总试验数和区间，而不是只显示百分比。

更多记录也不自动代表更多独立证据。连续同场景重试、同一物品或同一采集会话可能相关，应按适当独立单元分析。区间不能修复评估场景选择偏差，也不能替代在新场景上的测试。

代码对应：wilson_interval 的 n 与成功计数；评估日志中的 episode/session/object 元数据。

  • 区分点估计与不确定性。
  • 说明独立性及场景选择的限制。

两个模型都在相同 20 个场景上跑过，比较提升时为什么要保留配对？

参考解与分析

同一个场景可能对两个模型都特别难或特别容易。逐场景相减保留了这种共有难度信息，能回答在相同条件下新模型改善了多少。如果把两个模型的结果各自独立重采样，会丢掉原有对应关系，改变估计方式。

配对 bootstrap 应一起抽取某个场景的两条结果，或等价地重采样逐场景差值。若场景还属于相关会话，则需要按组重采样。除了平均差，还应检查改善和退化的场景；不能只挑选新模型成功、旧模型失败的片段。

代码对应：paired_difference=candidate−baseline 与 paired_difference[indices]。

  • 说明抽样单位是试验对。
  • 同时关注改善、退化及可能的组相关性。

提示
  • 不要使用简单的 p ± 常数；Wilson 的中心也会调整。
  • n=0 没有可估计的成功率，应明确报错而不是返回 0%。
参考实现与说明
参考实现
import math def wilson_interval(successes, trials, z=1.96):    if not isinstance(successes,int) or not isinstance(trials,int) or trials <= 0 or not 0 <= successes <= trials:        raise ValueError('invalid binomial counts')    if not math.isfinite(z) or z <= 0:        raise ValueError('invalid z')    p = successes/trials    d = 1+z*z/trials    center = (p+z*z/(2*trials))/d    half = z*math.sqrt(p*(1-p)/trials+z*z/(4*trials*trials))/d    return max(0.0,center-half),min(1.0,center+half)

9/10 的 95% 近似 Wilson 区间约为 59.6%–98.2%，说明少量试验下 90% 的点估计仍有很大不确定性。该解释依赖独立伯努利试验假设。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

只报告百分比不报告成功/试验数

9/10 与 90/100 的证据精度不同。保留原始计数、条件分组和区间。

把所有帧或高度相关 rollout 当独立样本

相关性会夸大有效样本量。按模型种子、场景或会话识别独立单位并据此重采样。

分别 bootstrap 两个配对方法

独立抽样破坏同一条件之间的关联。按配对索引同时抽取两边结果，直接计算差值分布。

只看区间是否重叠就判断方法差异

比较所需的是差值或等效性对应的统计问题。结合实际效应、试验设计及其区间，不从重叠图作绝对判断。

多次调参后仍称同一集合为盲测

这些条件已经反馈到开发过程。记录使用历史，并为最终方案保留未参与选择的评估条件。
