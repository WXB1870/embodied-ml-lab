训练诊断是把损失异常等现象转化为可区分假设，并用受控计算与对照定位首次偏离预期环节的过程。它不同于凭经验同时调整多个超参数。我们先建立样本、前向、目标、梯度和更新的完整链，再为各环节定义可观察基准，最后以单因素修复和回归检查结束排查。

前置知识：PyTorch 自动微分与计算图 · 训练循环与指标归约 · 混合精度训练

本章学习目标

  • 沿数据、计算图、梯度和优化器逐层收集证据。
  • 区分无梯度、零梯度、非有限梯度与未更新参数。
  • 设计小样本拟合和单变量对照，判断能排除什么问题。

01把训练拆成一条可检查的证据链

诊断证据链是按训练依赖顺序排列的一组可观察事实：数据正确、预测合理、目标匹配、梯度连通、更新发生。每项事实用于支持或排除具体假设。先建立这条链，再从异常结果定位首次分歧。

训练曲线不变只是现象，原因可能发生在数据、预处理、前向、损失、反向或更新。先建立顺序明确的证据链：样本和标签是否对应，模型看到的输入是否正确，预测是否依赖预期条件，loss 是否表达目标，参数是否收到梯度，优化器是否真正修改了这些参数。每一步都应有一个可以观察或断言的结果。

优先检查最早出现异常的位置。例如输入已经全零，后面的梯度图再完整也不能恢复缺失信息；目标被错位但模型能记住它，loss 可能下降得很好。不要把“能运行”“loss 有限”“有非零梯度”当作同一层次的正确性证明。将这些事实分开记录，能避免因一个指标正常就过早排除整条管线。

最小复现应保留引发问题的形状、Mask、模式和目标定义，同时去掉无关数据加载、日志服务和分布式组件。缩小系统是为了减少解释变量，不能把触发错误的条件一并删掉，再宣称原问题已消失。

02先审查一条样本，再审查一个 Batch

样本审查核对单条观测与标签的含义，批次审查核对拼接、填充和采样是否保持这些对应。两者检查不同层级。保留样本身份并追到损失，可以让问题从最终曲线回到具体记录。

在进入模型前检查原始样本与预处理后的 Tensor：值域、单位、通道顺序、类别编码、时间偏移、有效位和字段顺序。对图像可视化增强后输入，对序列列出时间戳与对应目标。将样本 ID 一直保留到 loss 计算，可以判断 shuffle、collate 或窗口切片是否错配。一个 shape 正确的 Batch 仍可能由不属于同一时刻的数据组成。

再查看同一 Batch 内是否存在重复样本、全无效样本、异常长序列或权重集中。用简单基线比较目标难度：连续目标的常数均值、分类的多数类或均匀概率，可以帮助发现训练效果是否仅达到平凡预测。基线只能参照，不能替代任务含义；若标签泄漏，复杂模型和基线都可能得到误导性结果。

可以再做标签置乱对照：在明确独立验证的前提下，随机打乱训练标签后，模型不应仍保持原先的样本外识别能力。若结果几乎不变，应检查目标是否被读取、指标是否使用真实标签、划分是否泄漏，以及模型是否仅利用类别频率。这个实验用于排查监督与评估管线，不是评价正式模型的最终方案。

保留可追踪的样本 ID 与数据约定

否则最终错误难以回溯到原始轨迹和具体变换。

检查：抽取一个样本贯通 Dataset、collate、模型输入和 loss，逐项对照同一 ID。

03预测与 loss 的合理数量级如何检查

数值基准是对特定输入和参数可以手算的预期输出或损失，例如零 Logit 的分类代价。它提供独立参照，而不是凭经验猜测合理数量级。下面先让模型满足可解释基准，再恢复复杂配置。

对已知输入和简单参数设置预测输出。例如把线性分类器权重与偏置清零，会得到相同 logits，单标签 K 类交叉熵应为 log K；回归模型输出零时，MSE 应等于目标平方的平均。这样的基准比经验判断“loss 大约应该是 1”更可靠，因为它来自当前目标的明确定义。

例：用均匀分类器检查接口

  1. 四类 logits 全为 0，Softmax 概率均为 14\frac1441​⁠。
  2. 无类别权重、无特殊归约的单标签交叉熵应为 −log⁡14=log⁡4≈1.3863-\log\frac14=\log4\approx1.3863−log41​=log4≈1.3863⁠。
  3. 若结果明显不同，先检查标签类型、重复 Softmax、ignore_index 与类别权重。

确定性基准能把 loss 解释从猜测变成可复查计算。

检查 loss 时将分项、误差和与有效数分别打印。总 loss 不变可能是某一项下降而另一项上升，也可能是显示精度不足；loss 突然缩小可能来自 Mask 大量丢失监督，而非预测改善。随机生成目标或噪声重采样会带来不可约波动，应区分单次 batch 误差、固定探针误差和真实独立验证误差。

04固定小批次实验能证明什么，不能证明什么

固定小批次实验在相同样本、初值和随机性下重复优化，用于检查一条管线是否能够学习已知简单目标。它隔离实现问题，却不估计泛化。实验设计和结论都需要限定在这一用途。

固定少量样本、初始化与随机因素，让模型反复拟合相同目标，是检查管线可学习性的有效方法。先关闭不必要增强和 Dropout，使用明确的损失分母与可解释输出范围；对简单合成目标，应该观察到预测和参数沿正确方向变化。若无法拟合，应优先排查图、标签、优化器与容量，而不是先上更大数据。

例：同样输入、相反标签，MSE 能降到多少

  1. 两条输入完全相同，目标分别为 −1 和 +1。任何确定性网络对同样输入都只能给出同一个预测 c。
  2. 平均平方误差为 12[(c+1)2+(c−1)2]=1+c2\tfrac12[(c+1)^2+(c-1)^2]=1+c^221​[(c+1)2+(c−1)2]=1+c2⁠，在 c=0 时达到最小值 1。
  3. 因此，把确定性网络加宽也不能让这组监督的 MSE 归零。应检查是否遗漏条件、错配标签，或是否需要预测条件概率分布。

小批次拟合前先判断目标是否可实现；这是条件均值分解在诊断中的应用。

但错误标签、泄漏输入和错误单位也可能被记住，因此小批拟合通过不证明语义正确或泛化良好。生成模型如果不断重采噪声和时间，训练对象并非固定样本，损失也可能有不可约方差。需要固定完整的条件—噪声—目标三元组做最小过拟合检查，再恢复真实随机训练协议，两种结果分开解释。

少量样本的过拟合速度还受容量和目标复杂度影响，不能要求任意模型都在几步内归零。最小实验的意义是为某个假设提供对照证据，而不是建立一个所有任务必须达到的统一 loss 阈值。

05把 None、零梯度和非有限梯度分开定位

None 表示该次检查没有得到参数梯度张量，零梯度表示得到的导数数值为零，非有限梯度表示出现 Inf 或 NaN。它们对应不同求导或数值状态。先区分现象，再沿预期路径排查。

参数 grad=None 可能因为它没有参与当前损失、被 detach、处于冻结状态，或检查时机不对。全零梯度则可能来自激活截断、损失局部平坦、相互抵消或无效监督；Inf/NaN 又是另一类数值异常。检查应放在 backward 后、下一次 zero_grad 前，并明确是叶子参数还是未 retain_grad 的中间激活。

使用 autograd.grad、retain_grad 或局部 hook 可以观察某段依赖，但不应无目的地对所有激活保存完整梯度。先沿期望路径选几个边界，判断信号在哪一处第一次消失。若上游模块之前有可训练参数，冻结模块内部仍可能需要输入梯度；误用 no_grad 就会留下后面有梯度、前面无梯度的典型分界。

梯度审计只输出一个全局范数

全局非零可以掩盖某个关键分支完全没有梯度。

检查：按模块记录 None 数量、有限性、范数和有效参数量，再定位首次异常边界。

06有梯度但不更新：检查优化器与执行边界

参数更新是优化器实际改变参数值的动作，与参数拥有梯度是两种关系。成员遗漏、旧对象、零学习率或跳步都可能让二者分离。下面将对象身份和真实位移作为直接证据。

参数参与求导和参与优化器是两种成员关系。新模块漏加参数组、替换了参数对象、学习率为零或 AMP 跳步，都可能导致有梯度却没有位移。优化器中还可能保留已不再使用的旧参数。应比较参数 ID，而不仅比较名称，并在 step 前后保存 detach().clone() 的快照来测量实际变化。

例：两种表面相似的失败

  1. 断图案例：主干输出 detach，后面分类器仍有梯度，但主干 grad=None，且主干不移动。
  2. 漏加优化器案例：分类器有非零梯度，optimizer.param_groups 却不包含它，分类器位移为零。
  3. 两者最终都可能表现为 loss 改善有限，修复位置却分别是计算图和参数组。

同时观察图连接、优化器成员与实际位移，才能分清原因。

如果位移非零但训练仍异常，再检查是否更新了正确对象、是否每次 forward 重新创建层、是否加载 checkpoint 后又覆盖参数、是否验证仍引用旧模型。测量相对位移 ∥Δθ∥2∥θ∥2+ε\frac{\lVert\Delta\theta\rVert_2}{\lVert\theta\rVert_2+\varepsilon}∥θ∥2​+ε∥Δθ∥2​​ 有助于比较不同层，但接近零参数时要解释分母；不要仅按一个统一比例判断所有层应具有相同学习速度。

把 optimizer.step 的调用次数当作有效更新次数

缩放器跳步、零学习率和遗漏参数都可能使调用不产生预期更新。

检查：对目标参数记录前后差值、实际 lr、in_optimizer 和 AMP 有限性结果。

07诊断日志、异常检测与性能剖析各有职责

诊断日志记录选定状态，异常检测定位出错的运算或反向路径，性能剖析测量时间和资源开销。三者回答不同问题。应围绕当前假设选择证据，而不将大量记录本身当作定位。

数值异常可用有限值检查、局部 hook 或 autograd 异常检测定位；训练速度与内存瓶颈需要 profiler、同步计时和分配统计。高耗时不等于梯度错误，低吞吐也可能来自数据读取或频繁 CPU/GPU 同步。不要把每一步大量 item()、打印和全模型梯度拷贝加入正式训练后，再用被诊断工具拖慢的结果判断性能。

日志保存标量或 detach 后的小摘要，避免不断保留带图 GPU 张量。定期抽样记录比每步保存全部激活更适合长期训练。发现异常时保存能重放问题的最小样本、配置、随机状态和错误信息，并减少无关输出。清晰的日志应该让人回答一个假设，而不是产生更多无法解释的曲线。

08用单因素修复和回归测试结束排查

定位故障还需要一个闭环：只修改对应因素，再重放同一输入，确认预期机制恢复。将最小反例转为回归检查，可以保留这次诊断的因果证据，并防止相同错误在后续结构调整中重新出现。

配套代码在同一数据与初始化上构造正确、断图和漏加优化器三条路径，并用不同断言识别。修复时只改变对应因素，再重放完全相同输入，确认异常证据消失且预期更新恢复。若同时更换学习率、模型、数据和损失，即使训练改善，也无法知道真正原因，更难判断后续是否会复发。

将反例保留成小回归测试：比如新模块必须出现在 optimizer 中、冻结区之前的 Adapter 必须有梯度、有效零标签不能被 Mask 掉。测试应检验业务上重要的计算约定，不需要把实现每一行复制一遍。修复训练链路后，再恢复独立验证、真实增强和闭环评估，确认局部改动没有引入新的目标偏差。

一个完整诊断报告应包含现象、假设、控制变量、支持或反驳证据、修复以及剩余边界。比起“调了一下就正常”，这种记录能帮助下一次快速识别相似故障，也能把经验变成可复用的知识。

对于恢复后才出现的训练退化，保存加载前后的同一输入、模型状态和随机状态，对比下一次前向、梯度与更新。若前向已不同，先查模式、预处理与权重；前向相同而更新不同，再查优化器状态、scheduler、AMP 与累积边界。按首次分歧分层定位，能避免从整个训练曲线倒推所有可能原因。

诊断应尽量复用已经出现故障的同一个训练对象。共同训练项目保留正常 Dataset、Mask 和 4→2 模型，只在 verify_optimizer_diagnosis 中漏掉 bias 的优化器成员；观察到非零 bias 梯度但零参数位移。另一个 verify_masks 只改变无效区或有效标签，用输入不变性与主动拒绝区分 Padding 处理错误。每个实验只改变一个假设，避免换一个模型后损失下降却无法解释原来的问题。

训练诊断的结果应是一个可复现、可反驳并能回归检验的解释。沿数据到参数的依赖找到证据，单独改变对应因素，再复查预期行为，才完成了从现象到修复的过程。
