自动微分是根据程序实际执行的运算及其局部导数，自动计算复合函数导数的方法。PyTorch 的 Autograd 在前向中记录计算图，反向时沿图应用链式法则，将损失梯度传回相关输入和参数；优化器随后才负责更新参数。本章先建立这条完整流程，再区分梯度累积、参数冻结、模式切换与断图，最后验证真正发生了什么更新。

前置知识：线性代数与矩阵求导

01前向建图、反向求导、优化器更新是三个动作

计算图记录张量运算之间的依赖，反向求导沿这些依赖计算梯度，优化器更新则使用梯度改变参数。这三者分别管理函数、导数和参数状态。先把它们连成一次训练步，再检查某个参数为何参与或没有参与学习。

在默认梯度模式下，输入中有需要梯度的张量时，可微运算会记录反向所需的信息，形成动态计算图。loss.backward() 从输出种子开始，按逆序应用局部导数，将叶子参数的贡献累积到 .grad。optimizer.step() 再读取这些梯度与内部状态执行更新。一个参数 requires_grad=True，只说明允许追踪它，不说明它已参与当前损失，也不说明优化器会更新它。

训练时通常每次重新前向产生一张新图，反向结束后不再需要的中间保存量可释放。Python 变量还引用着输出，不等于整张反向图中的所有缓存都可再次使用。重复对同一前向图 backward 需要明确理由；通常应重新前向，而不是把 retain_graph=True 添加到所有训练步。保留图会增加内存生命周期，也不能修复已经 detach 的依赖关系。

02叶子、非叶子与梯度累积

叶子张量是求导图中直接提供的输入或参数，非叶子张量是运算产生的中间结果。梯度累积是多次反向将贡献加到叶子的 .grad 中。这个区分解释了为什么中间值参与求导，却未必保存自己的梯度。

用户直接创建且需要梯度的张量，或者 nn.Parameter，通常是求导图中的叶子；运算产生的中间张量是非叶子。默认情况下，非叶子的梯度会用于继续传播，但不会保存在它自己的 .grad 中。想检查某个激活可调用 retain_grad 或使用合适的 hook。看到中间 Tensor.grad 为 None，不能立即判断这条路径没有参与反向。

叶子的 .grad 默认累积而非覆盖，因此连续两次对独立图 backward 会把两个梯度相加。优化器的 zero_grad 只清理其管理的参数；若某些参数未进入优化器但仍求导，它们可能积累旧梯度。set_to_none=True 与写入零也有语义差异：未参与反向的参数可以保持 None，许多优化器会跳过它；有零梯度的参数仍可能受到已有动量或权重衰减影响。

把 grad=None 与全零梯度混为一谈

None 可能表示未参与图、被冻结或未保留中间梯度；零则是一个实际计算出的数值。

检查：在 backward 后、zero_grad 前检查叶子参数，并标记 requires_grad、优化器成员和 grad 状态。

03冻结参数不等于切断它对输入的导数

冻结参数是停止对选定参数求梯度或更新；切断计算图则移除某段上游依赖的求导路径。冻结模块仍可能需要把输入梯度传给前面的可训练模块。下面沿同一条 Adapter 路径比较这两种操作。

考虑 x→可训练 Adapter→冻结模块→损失。将冻结模块参数设为 requires_grad=False，只是不求这些参数的梯度；为了更新前面的 Adapter，仍需计算冻结模块输出对输入的导数。若把冻结模块前向包进 no_grad，或者把输出 detach，通向 Adapter 的路径会被截断。能否停止记录，取决于前面是否还有要训练的量。

如果冻结编码器直接接收固定数据，前面没有可训练处理，且后续只训练下游模块，那么在编码器内部使用 no_grad 可以是合理的效率选择。它的输出仍能作为常量输入参与后续可训练 Linear 的参数求导。两种结构都属于“冻结骨干”，但计算图的依赖关系不同；应从 loss 向前检查每一个需要更新的参数，不能仅按模块名称决定梯度上下文。

例：冻结乘数仍要把梯度传给输入

  1. 设可训练 x=2x=2x=2⁠、冻结常数 w=3w=3w=3⁠，y=wxy=wxy=wx⁠，L=y22L=\frac{y^2}{2}L=2y2​⁠。
  2. 前向 y=6y=6y=6⁠；∂L∂x=yw=18\frac{\partial L}{\partial x}=yw=18∂x∂L​=yw=18⁠。w 不更新，但乘法仍参与对 x 的求导。
  3. 如果在计算 y 时断图，则 L 无法通过这条路径给 x 传回 18。

冻结一个参数与删除整个算子的反向关系并不等价。

先画可训练参数的位置，再放 no_grad

冻结区内部的输入 Jacobian 可能仍是上游训练所必需的。

检查：用最小标量或小 Linear 链复现结构，分别核对被冻结参数与前置 Adapter 的梯度。

04eval、no_grad 与 inference_mode 分别控制什么

eval 选择模块的评估行为，no_grad 暂停反向图记录，inference_mode 还会关闭面向自动微分的一些额外追踪。它们分别控制前向行为与求导记录，并不互相替代。先分清作用，再组合成验证或推理过程。

model.eval() 改变具有训练/评估行为差异的模块，例如 Dropout 和 BatchNorm，但不会关闭自动微分。torch.no_grad() 不记录其中运算的反向图，但不会自动把 Dropout 切换成评估行为。做常规验证通常同时设置 eval 和 no_grad，二者解决不同问题；验证完成后恢复 train，避免后续训练一直使用评估行为。

inference_mode 进一步减少梯度跟踪开销，但其创建的张量在之后参与需记录的 autograd 运算时有更严格限制。不能因为名称叫“推理”就无条件套到“冻结编码器+可训练下游”的训练环节。先使用语义清楚的 no_grad，再根据实际边界验证更强模式是否适用。对需要输入梯度的可视化、敏感度分析或优化任务，eval 下仍应保留梯度模式。

例：四种模式组合

  1. train + 默认梯度：Dropout 随机，通常用于训练。
  2. eval + 默认梯度：Dropout 关闭，但仍能对输入或参数求导，适合某些敏感度分析。
  3. train + no_grad：仍可能有随机 Dropout，且不记录反向。
  4. eval + no_grad：普通确定性模块的评估配置，但算法中其他随机采样仍需另行固定。

模式开关控制不同维度，不应把其中一个当作另一个的别名。

05detach、clone、item 和重新构造 Tensor 的区别

detach 断开求导关系但通常共享数据，clone 复制数据且通常保留求导关系，item 则取出普通 Python 标量。这些操作分别改变计算图、存储或数值对象。先确定自己需要快照还是断图，再选择对应操作。

detach 返回与原张量共享数据但不连接原求导图的张量；clone 通常复制数据并保留求导路径；detach().clone() 同时断图并获得独立副本。若对 detach 后的别名做原地修改，原张量的数值也可能改变。需要记录快照时应区分“我只想不反传”与“我也想避免后续修改影响这份数据”。

item 将单元素 Tensor 变成 Python 数值，适合日志，但把这个值重新包装为 Tensor 并不能恢复原图。类似地，用 torch.tensor(existing_tensor) 重新构造一般会切断原有求导联系，不能用 requires_grad=True 再接回旧路径。对于可微组合应使用 stack、cat 和张量运算；对于指标与日志则应主动 detach，避免长期保存带图对象。

重新 requires_grad 不能修复已经断开的历史

新叶子可以继续参与后续求导，但它不知道旧张量是怎样算出来的。

检查：从 loss.grad_fn 向前审查 item、detach、NumPy 转换和重新构造 Tensor 的位置。

06原地操作与无效计算为何会破坏反向

原地操作是直接改写张量已有存储的运算。自动微分若还需要被覆盖的前向值，就无法按原函数正确反传；无效数值也可能沿保存的局部导数传播。下面追踪反向需要什么，而非仅靠程序有没有报错判断。

autograd 可能保存前向值供 backward 使用。若之后原地改写这些值，反向需要的数据就与原计算不一致，框架通常借助版本检查报告错误。不能用 .data 绕过检查来“修复”，那可能让梯度悄悄错误。优先采用非原地表达式，只有在理解别名与保存需求之后再考虑原地优化。

对非法运算先计算再 Mask 也可能有问题。例如先除以零，再选择不包含该结果的输出，反向仍可能经过非法的局部导数并产生 NaN。应在运算前筛选有效输入，或构造只在合法定义域内执行的计算。torch.where 的两个分支往往都已先被求值，因此它不等于 Python 的惰性条件执行；安全分母与有效索引需要明确设计。

07保留原图与对导数继续求导

保留计算图是让同一次前向还能再次反传；高阶求导是把导数本身当成函数继续求导。retain_graph 与 create_graph 分别服务于这两个需求。先明确要重复使用哪一张图，再理解相应开关的作用。

autograd.grad 返回指定输入的导数，默认不把结果累积到参数 .grad。retain_graph=True 保留本次反向使用的原图，便于从同一前向再次求导；create_graph=True 则记录求导运算，建立“导数作为函数”的计算图。前者解决原图是否被释放，后者决定能否沿求导结果继续传播，两者不是更省内存与更费内存的同义开关。

例如 f(x)=x3f(x)=x^3f(x)=x3⁠，第一次导数 g(x)=3x2g(x)=3x^2g(x)=3x2⁠，第二次为 6x6x6x⁠。若第一次只保留原图，返回的数值 3x23x^23x2 通常没有供继续求导的图；再次从原来的 f 求导仍然只会得到一阶导数。用 create_graph=True 得到 g 后，再对 g 求导，才是在计算二阶信息。普通训练只需要一阶梯度时，不必为此额外建图。

这个区别会直接影响梯度惩罚。若 g(θ,x)=∂fθ(x)∂xg(\theta,x)=\frac{\partial f_\theta(x)}{\partial x}g(θ,x)=∂x∂fθ​(x)​⁠，并把 ∥g∥22\lVert g\rVert_2^2∥g∥22​ 加入训练目标，它对 θ\thetaθ 的导数经过 ∂2f∂θ ∂x\frac{\partial^2 f}{\partial\theta\,\partial x}∂θ∂x∂2f​⁠。必须让输入梯度的计算本身可微；把 g.detach() 后再平方，数值看似相同，却不再通过这一项训练 θ\thetaθ⁠。某些线性函数的高阶导为零，求导结果也未必依赖所有输入，应按数学依赖处理未使用项。

对共享同一前向图的多个任务，可以加权求和后一次 backward，也可按需多次求导并保留原图。分开记录梯度时，参数集合与展平顺序必须相同，未使用参数保留零占位。allow_unused 只允许表示没有依赖的输入，不证明它们得到了训练；非标量输出还必须给出与目标一致的 VJP 种子。

Python
import torch x = torch.tensor(2., dtype=torch.float64, requires_grad=True)(first,) = torch.autograd.grad(x**3, x, create_graph=True)(second,) = torch.autograd.grad(first, x)assert first.item() == 12. and second.item() == 12. z = torch.tensor(2., dtype=torch.float64, requires_grad=True)(value_only,) = torch.autograd.grad(z**3, z, retain_graph=True)assert not value_only.requires_gradprint("first:", first.item(), "second:", second.item())

在 x=2x=2x=2 处，一阶和二阶导数碰巧都为 12，但来源不同。后半段只保留原图，返回的一阶导数没有继续求导所需的依赖；把 retain_graph 改成 create_graph 后再比较其 requires_grad。

08从计算图到真实参数更新的验证

理解单个开关后，需要把它们放回一次完整训练步验证。依次检查图连接、叶子梯度和实际参数位移，才能证明预期模块确实受到监督，也能发现只查看 requires_grad 无法识别的问题。

用固定输入和参数快照做一次完整训练步：先清零，执行前向，确认 loss 有正确 grad_fn，再 backward，检查目标参数的 grad 是否有限，最后 step 并比较参数差。冻结参数应保持不变，需要更新的模块应实际出现在优化器中；合法的零梯度应有可解释原因，不能把所有未变化都视为程序故障。

演示冻结中间模块并训练其前面的 Adapter，专门区分“冻结权重”和“停止反传”。还应通过反例把冻结模块放进 no_grad，观察前置参数失去梯度的现象。这样的对照比查看一行 requires_grad 标记更有说服力，因为它验证的是完整计算依赖。

最后检查日志不会保留图：记录 loss.item()、detach 后的小统计量或独立 CPU 副本，不要不断把带图的 GPU 输出加入列表。重复几次后内存持续增长时，优先查对象引用、保留图和 hook，而不是立刻把问题归因于模型越来越大。

需要把本课 API 对应到完整计算图时，可回到 MLP 的同一 17 参数案例：X、W₁、b₁、W₂、b₂ 五组导数由显式 VJP 与 autograd 逐项比较；真正的 SGD 只更新四组模型参数。中间量 retain_grad 与叶子 .grad 的区别，应以该计算图中的变量角色解释，而不是将所有 Tensor 都视作需要学习的参数。

自动微分计算的是程序真实依赖的导数。正确训练还需要让参数进入计算图、让所需梯度保持连通，并让优化器实际管理这些参数；冻结、评估模式和断图应按这三个职责分别选择。
