推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

冻结骨干后为什么仍可能需要保存它的反向图？

参考解与分析

如果骨干前面有可训练 Adapter，损失对 Adapter 的导数必须乘上骨干对输入的 Jacobian。骨干权重不更新，并不代表它对输入的函数关系可以从链式法则中删掉。

若原始输入不需要梯度，且只训练骨干后面的头，才可能不需要这段图。演示对比正常冻结与 detach：前者 Adapter 有梯度，后者断开这条路径。

代码对应：forward_frozen；演示 STEP 2 和 STEP 3 的 Adapter.grad 检查。

  • 能画出需要梯度的实际路径。
  • 能说明何时 no_grad 合理、何时会错误切断训练。

requires_grad=True 且存在梯度，能否证明某个模块已经被更新？

参考解与分析

不能。参数还必须在优化器参数组中，step 必须真正执行，学习率和有效梯度也不能让更新为零。旧梯度、优化器状态与实际训练分支也会影响结果。

检查应包括参数身份、requires_grad、grad 是否存在及有限、优化器成员关系，以及更新前后参数差。eval 只影响特定层的行为，不能替代上述验证。

代码对应：计算图与梯度检查；training-diagnostics 课程中的参数审计提供完整实现。

  • 能列出梯度之外还需检查的条件。
  • 能区分 eval、冻结和 optimizer.step 的职责。

冻结一个乘法因子，手算仍应传回的梯度

模型预测 y=v*w*u*x，损失 0.5*(y-target)^2。w 冻结，u 和 v 可训练。返回 (du,dv)，不要把 w 冻结误解为对 u 的梯度也为零。

参考实现与说明
参考实现
def chain_grads(x, u, w, v, target):    error = v * w * u * x - target    du = error * v * w * x    dv = error * w * u * x    return du, dv

在真实网络中，“冻结 w”与“detach 中间值”会产生不同的图结构；后者才会截断通往上游参数的路径。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

冻结中间模块就套 no_grad

若其前面有可训练 Adapter，仍需通过冻结模块反传。画出参数依赖并用最小例子核对前置参数梯度。

验证时只用 no_grad 而不 eval

Dropout 或 BatchNorm 仍可能保持训练行为。评估配置需同时考虑模块模式与求导模式，并在结束后正确恢复。

用 retain_graph=True 修复所有 backward 报错

它只保留当前图，不能恢复 detach，也可能导致内存增加。普通训练每步重新前向；多次求导才按需保留。

先非法计算，再用 Mask 掩盖

非法局部导数可能污染 backward，NaN×0 也不会消失。应在除法、对数等运算之前保证定义域合法。
