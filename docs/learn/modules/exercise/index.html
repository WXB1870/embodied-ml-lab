推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

一个层能参与前向并得到梯度，是否一定会被 optimizer.step 更新？请给出完整检查顺序。

参考解与分析

不一定。层可能放在未注册的普通 Python list 中，或者在优化器创建后才加入，导致优化器没有持有它的参数对象。Autograd 能算梯度并不意味着优化器会自动扫描发现这些参数。

先检查 named_parameters 中是否有目标参数，再看 requires_grad 和实际 grad，接着确认同一参数对象出现在 optimizer.param_groups，最后比较一次更新前后的值。若梯度本来为零，还应结合损失和结构判断，而不是直接断定优化器错误。

代码对应：对比 id(parameter) 与优化器参数组里的对象 ID，保存参数更新前后的独立快照。

  • 区分注册、梯度与优化器归属。
  • 包含一次实际参数变化检查。

为什么 best_state=model.state_dict() 可能不能保留最佳模型？Buffer 是否也需要保存？

参考解与分析

state_dict 通常包含引用当前模型张量的值，后续原地参数更新可能使内存里的 best_state 也变化。需要独立快照时使用 deepcopy，或立即序列化，而不是只复制最外层字典。

持久 Buffer 也会影响模型函数，例如归一化统计量或 BatchNorm 运行状态，所以通常需要随权重保存。它们不是优化器学习的参数，但缺失时仍可能让恢复后的输出不同。

代码对应：在保存快照后做一次更新，再加载到新模型并比较更新前的输出。

  • 指出浅引用导致快照变化的原因。
  • 说明持久 Buffer 对前向与恢复的作用。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

用普通 list 装层而没有注册

forward 仍可能运行，但 parameters/to/state_dict 未必能发现这些层。使用 ModuleList/ModuleDict，验证状态键和设备。

forward 中每次新建 Linear

参数随调用重建，优化器不能按预期复用和更新。把稳定权重放在构造或明确初始化阶段。

只看 grad 不检查优化器对象

新增层、替换参数或加载方式可使 optimizer 持有旧集合。对照参数对象 ID，并实际比较一次更新。

把统计量直接放普通 Tensor 属性

设备迁移与保存容易遗漏。影响前向且不应学习的 Tensor 可注册为 Buffer，并明确是否持久。

用浅 state_dict 引用保留最佳状态

后续更新可能改变底层 Tensor。深拷贝或及时保存，再在新实例中验证旧输出恢复。
