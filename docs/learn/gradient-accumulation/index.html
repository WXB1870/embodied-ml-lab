梯度累积是把一次有效批次拆成多个微批次、分别前向与反向，将梯度累加后只更新一次参数的方法。它降低同时保存的激活量，但是否等价于大批次取决于目标分母、参数保持不变及前向是否受分块影响。本章先认识一个完整累积周期，再定义变长计数、尾批、裁剪、精度缩放与进程同步的边界。

前置知识：PyTorch 自动微分与计算图 · 损失、掩码与归约 · 梯度下降、动量与 AdamW

本章学习目标

  • 推导不等长微批次对应的全局平均损失与梯度。
  • 写出清零、累积、裁剪、更新和调度的正确边界。
  • 用完整批次作为数值参照，验证参数更新等价性。

01梯度可加的前提：同一参数点、同一目标

梯度可加性是同一参数点处，加权目标之和的导数等于各目标导数之和的性质。梯度累积利用它分开计算一个有效批次。先固定参数与每项系数，才能把累积和多次小步更新区分开。

设一个完整批次的目标为 L=1N∑iℓiL=\frac1N\sum_i\ell_iL=N1​∑i​ℓi​⁠。微分的线性性允许把样本分成多个微批次，分别计算它们对同一组参数的梯度，再相加。这里关键是所有微批次前向都使用相同参数，且每项损失带有与完整目标一致的系数。若每个微批次都 optimizer.step，后面的梯度是在另一参数点计算，已经变成多次小批更新，不再是同一次大批梯度。

例：相同两个样本，更新顺序可以改变结果

  1. 令 L1(θ)=12(θ−1)2L_1(\theta)=\frac12(\theta-1)^2L1​(θ)=21​(θ−1)2⁠、L2(θ)=12(θ+1)2L_2(\theta)=\frac12(\theta+1)^2L2​(θ)=21​(θ+1)2⁠，从 θ=0\theta=0θ=0 开始。两项在同一点的梯度分别为 −1 和 +1，平均梯度为 0，因此一次累积更新仍为 0。
  2. 若改成两个 SGD 小步，每步学习率 0.1，先用 L1L_1L1​ 得到 θ=0.1\theta=0.1θ=0.1⁠，再用 L2L_2L2​ 的当前梯度 1.1 得到 θ=−0.01\theta=-0.01θ=−0.01⁠。
  3. 把顺序反过来，结果为 +0.01。即使把每个小步学习率改为 0.05，仍分别得到 −0.0025 或 +0.0025，而累积更新仍为 0。

逐微批 step 会在新的参数点重新求梯度；把学习率按微批数缩小，也不能普遍恢复一次大批更新。

梯度累积主要减少同时驻留的激活，不会按同样比例减少参数、梯度和优化器状态。一个微批次反向完成后，它的图可以释放，叶子参数上的 .grad 保留数值供后续相加。通常无需 retain_graph=True，因为每个微批次都是新的前向图。把所有微批 loss 保留到最后一次 backward，可能仍然保留全部激活，失去预期的内存优势。

理解累积时先写出完整目标，再设计分块过程；不要先套 loss/K 模板再解释它平均了什么。样本数、有效 token 数、动作维度与权重都可能影响分母，尤其是机器人轨迹长短不同的情况。

02为什么 loss 除以累积次数只在特定条件下成立

有效元素数是当前目标真正平均的监督标量数量，微批局部均值则只平均该微批。仅在相应计数相等时，平均局部均值才等于总体均值。下面由完整目标推导每次反向应使用的系数。

若每个微批次都有相同的有效元素数 n，且其局部损失 LkL_kLk​ 都是这些元素的平均，完整目标为 1K∑kLk\frac1K\sum_k L_kK1​∑k​Lk​⁠，因此每次反向前除 K 正确。若 nkn_knk​ 不同，正确目标则为 ∑knkLk∑knk\frac{\sum_k n_kL_k}{\sum_k n_k}∑k​nk​∑k​nk​Lk​​⁠。把局部均值直接平均，等于让微批次等权，而不是让元素等权；最后一个不足大小的批次尤其容易触发这个错误。

一种直接实现是先知道本次更新所有微批次的总有效数 N，将每个未归约误差和 SkS_kSk​ 除 N 后 backward。若目标分母只依赖数据而不依赖参数，也可先累计误差和对应的梯度，再在更新前按同一 N 缩放梯度。后一种方式与 AMP、DDP 和裁剪组合时必须明确顺序，不能先裁剪局部梯度再期望恢复完整目标。

例：不等长微批次不能简单二等分

  1. 微批次 A 有 2 个有效元素，平均梯度为 10；B 有 6 个有效元素，平均梯度为 2。
  2. 完整有效元素平均梯度为 2×10+6×28=4\frac{2\times10+6\times2}{8}=482×10+6×2​=4⁠。
  3. 两个局部均值各除 2 再相加得到 6，方向可能相同但更新幅度和任务权重已经错误。

有效元素不等时，用真实计数加权，而不是固定累积次数。

有效 Batch 大小只按样本条数估算

不同轨迹包含的有效监督数量可以相差很大；样本 Batch 与元素 Batch 不一定等价。

检查：同时记录每次更新的样本数、有效时间步和有效标量数，并手算两块不等长输入。

03清零、反向、更新与尾批的边界

累积周期是多次微批反向共同组成一次参数更新的范围。周期开始清空旧梯度，内部保持参数固定，末端统一更新。尾批长度不足时也需按实际监督量定义，而非默认补足完整周期。

一个累积周期开始前清零梯度；周期内多次 forward/backward；周期结束执行一次更新；再为下一个周期清零。若在每个微批次开头 zero_grad，前面的累积会被丢掉。若周期结束忘记清零，旧梯度会混入下一次更新。最好用显式的 optimizer_step 和 micro_step 计数，避免把这些边界隐藏在复杂循环条件里。

数据迭代结束时可能剩下不足 K 个微批次。可以按实际有效数完成这一更新，或者按预先声明的协议丢弃；不能仍固定除 K，却宣称与当前剩余数据的均值等价。空监督微批次可以对分子和计数贡献零，但整个更新全无效时必须明确跳过策略。日志、scheduler 和 checkpoint 的保存位置也要对应这个更新边界。

如果中途恢复训练，需要知道是否允许在累积周期内部保存。只保存模型和优化器而不保存已累计梯度、计数与数据位置，会丢失半个更新。更简单的协议是在完整 step 边界保存，并在文档中明确这一点。

04裁剪是非线性操作，应在完整梯度形成后进行

梯度裁剪是对已经形成的梯度作幅度限制，它通常是非线性操作。先分别裁剪微批再相加，通常不等于对总梯度裁剪。若要保持同一批次更新，应先完成累积再执行裁剪。

全局范数裁剪将最终梯度按同一比例缩放。一般有 clip⁡(g1)+clip⁡(g2)≠clip⁡(g1+g2)\operatorname{clip}(g_1)+\operatorname{clip}(g_2)\ne\operatorname{clip}(g_1+g_2)clip(g1​)+clip(g2​)=clip(g1​+g2​)⁠，所以逐微批次裁剪再累积，会改变更新方向与大小。正确顺序通常是完成全部反向、还原 AMP 缩放、必要的全局归约，再对完整参数集合裁剪一次，最后 step。

例：局部裁剪会改变结果

  1. 一维微梯度为 g1=2g_1=2g1​=2⁠、g2=−1g_2=-1g2​=−1⁠，阈值为 0.5。
  2. 分别裁剪后为 0.5 和 -0.5，相加得到 0。
  3. 先求和得到 1，再裁剪得到 0.5。

一次完整更新与逐块裁剪是两个不同算法。

裁剪参数集合也应一致。若只裁剪某一小头，却把总梯度范数当作整个模型统计，会误判训练稳定性。对于分片优化器或特殊分布式结构，全局范数如何得到需要对应实现；这里的公式以同一进程可访问全部目标梯度为基础。检测到 NaN/Inf 时，应定位来源，而不是让 max_norm 成为掩盖非法数值的手段。

记录裁剪前范数与真实参数位移

裁剪是否频繁触发、是否压制了正常信号，需要实际统计。

检查：在固定累积周期内比较裁剪前后梯度，并确认只在周期末调用一次。

05AMP 累积必须保持同一个缩放因子

梯度缩放使反向梯度带上同一正比例因子，unscale 才将它恢复到原目标的单位。累积周期内各项必须使用一致因子，否则无法用一次还原得到正确总梯度。下面将缩放边界接到更新边界。

使用 GradScaler 时，整个有效批次的梯度要在同一缩放因子下累加。如果第一个微批次后就 unscale，再累加第二个缩放后的梯度，两者单位不同，无法得到正确总梯度。类似地，在周期中途 update 改变缩放因子，会让不同微批次乘上不同倍数。缩放检查、跳步和尺度更新应与完整有效批次对齐。

通常每个微批次用同一个 scaler.scale(loss_part).backward，在周期末 unscale_ 一次，裁剪后 scaler.step，再 scaler.update。每个 optimizer 的 unscale_ 不能在一次更新之间重复调用。若一个周期出现非有限梯度，跳过的是这次完整更新；scheduler 是否前进应遵守实际更新计数协议，并记录跳步事件。

梯度缩放只处理数值范围，不会自动修复错误的 loss_part 分母。应先在 FP32 下证明累积等价，再引入 AMP 并用合理容差比较；否则数学归约错误与低精度差异会混在一起。

在微批次末尾调用 scaler.update

这样可能使同一 .grad 中混入不同单位的梯度。

检查：把 unscale、clip、step、update 与清零放到同一个明确的更新边界。

06DDP 累积还多了进程维度

分布式累积同时包含微批维度和进程维度：本地先累加，进程间再按同步协议组合。默认 DDP 的平均行为并不自动补齐不同有效计数。需要先定义全局目标，再推导各 rank 的贡献。

普通 DDP 会在进程间平均梯度。若各 rank 和微批次有效数不同，平均本地均值不等于全局有效元素均值。应先得到全局有效数 N，并按 DDP 的平均行为对本地误差和缩放；在默认平均梯度协议下，本地反向目标可写为 world_size SlocalN\frac{\mathrm{world\_size}\,S_{\mathrm{local}}}{N}Nworld_sizeSlocal​​⁠，使平均后回到全局目标。自定义通信 hook 或不同归约方式需要重新推导。

为了减少通信，可在前几个微批次使用 no_sync，并在最后一次前向与反向恢复同步。no_sync 的上下文需要包含 forward，不能只包 backward。所有 rank 必须以一致的顺序参与所需集合通信；某个进程没有本地有效元素，也不能无协调地跳过同步。这里应先追求正确更新，再考虑通信优化。

07大批次与累积为何可能仍不完全相同

大批次等价要求分块不改变每个样本对应的前向函数与目标。训练态 BatchNorm、批内对比或随机操作可能不满足这个条件。梯度加法恒等式本身不能消除这些前向差异。

数学上的梯度加法等价假定每个样本的前向行为不随分块变化。训练态 BatchNorm 使用微批统计，分块后统计不同，因此不一定等价于一次大批前向。Dropout 随机 Mask、数据增强、批内对比负样本和其他跨样本运算也会改变目标。把损失分母修正正确，是必要条件，但并非所有模型的大批等价充分条件。

浮点累加顺序还会带来小数值差异。验证可先选择没有跨样本状态和随机性的模型，使用 float64，关闭或固定随机因素，比较 loss、逐参数梯度与更新后的参数；确认基础目标一致后，再逐项加入真实结构。若差异来自有意的微批统计，应记录这一边界，而不是不断放宽容差掩盖原因。

08用一次完整更新做端到端对照

各项等价条件最终需要在一次完整更新中同时成立。复制同一模型和优化器状态，逐项比较整批与分块的梯度及参数，比只观察两条相似损失曲线更直接，也能发现计数边界上的错误。

示例用不等长、带 Mask 的微批次复现完整批次更新。首先复制同一初始模型和优化器状态，随后分别走整批与分块路径，最终逐元素比较参数。只比较最终 loss 太弱：两个错误实现也可能得到接近的标量；比较梯度更直接，而参数对照还能发现 step 次数和优化器状态边界错误。

扩展检查时覆盖最后不足 K 的尾批、某一微批次全无效、不同动作维数以及权重不等的样本。日志同时报告误差和、有效数、微批次数、同步次数与优化步数。确认这些计数和目标定义一致后，再调节累积次数以适应显存或吞吐，而不是把更大的名义 Batch 直接当作更好的训练方案。

保存实验配置时明确哪些操作在微批级、哪些在更新级：增强与前向通常在微批级，裁剪、optimizer.step、按步学习率与 scaler.update 通常在更新级。这样才能让后续改动、断点恢复和分布式扩展保持可解释。

本章的局部梯度对照继续保留；完整组批后的验证统一在共同训练项目的 verify_accumulation。同一个 TokenRegressor 和七条 episode 分成有效数 10、30 的两批，正确反传是 S₁/40 与 S₂/40；控制组故意对局部 mean 再平均。除了所有梯度，还对照一次 SGD 后的参数。这一等价不含 BN、Dropout 或批间随机交互，不能推广为任意网络逐比特相同。

梯度累积保留的应是一次明确更新：相同参数、相同监督权重、完整总梯度和统一更新边界。节省激活内存是实现效果，与大批次等价则是带条件的数学关系，需要分别检查。
