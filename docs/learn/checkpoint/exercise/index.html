推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

只加载 model.state_dict 后继续优化，与恢复一个完整训练 Checkpoint 有哪些不同？

参考解与分析

模型状态恢复参数和持久 Buffer，但不自动恢复 Adam 动量、学习率调度进度、混合精度缩放器、全局更新步数或随机状态。因此相同权重出发的下一步参数更新也可能不同。

数据版本、归一化、动作定义和采样位置同样影响训练含义。应明确这是从已有权重启动新的微调，还是尝试延续原实验；两者都可能有用，但不能用同一个“完全恢复”描述。

代码对应：检查 checkpoint.keys()，核对 optimizer、scheduler、RNG 与数据配置是否各有明确来源。

  • 至少说明优化器和学习率状态的差别。
  • 提及数据约定或随机/采样状态影响下一步。

为什么恢复随机状态应放在模型重建之后？怎样证明恢复结果足以继续下一步，而不只是加载没有报错？

参考解与分析

模型重建通常随机初始化参数，会消耗随机数。若先恢复 RNG 再重建，就把状态向前推进了；应完成构造和状态加载后，再恢复本实验实际使用的各个随机源。

在受控环境下保存一个检查点，不中断地执行下一步得到参考；重新构造并恢复后执行同一步，比较输入、loss 和参数。这个实验验证当前环境下的范围，不自动保证跨硬件、跨版本或多进程预取逐位一致。

代码对应：对照 expected_loss、actual_loss 和所有参数，同时检查 RNG 恢复前后是否还有随机调用。

  • 解释随机初始化会消耗 RNG。
  • 给出不中断与恢复后下一步对照，并说明验证范围。

提示
  • dict.copy 只拷贝最外层，里面的列表或字典仍然可能共享。
  • 标准库 copy.deepcopy 可以递归创建独立状态。
参考实现与说明
参考实现
import copy def snapshot_training(weights, optimizer_state, step):    if not isinstance(step, int) or step < 0:        raise ValueError("step 必须是非负整数")    return {        "weights": copy.deepcopy(weights),        "optimizer": copy.deepcopy(optimizer_state),        "step": step,    }

内存里的最佳权重快照若共享底层状态，就可能随下一次更新变化；这是恢复与最佳模型选择中的常见陷阱。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

只载入权重就称为严格续训

动量、调度器、精度和数据状态可能不同。区分迁移初始化与恢复原实验，并提供下一步对照。

strict=False 后忽略所有缺失键

这可能漏掉关键模块或 Buffer。逐项解释预期差异，核对配置与加载后的函数输出。

只重设最初 seed，不恢复当前随机状态

随机序列会从头开始。保存实际生成器状态，并考虑重建模型与 Worker 的随机数消费。

累积窗口中间只保存参数和优化器

已经累积的梯度及有效分母丢失会改变下一次更新。选择完整更新边界，或实现对应完整状态恢复。

把最佳权重与最新优化器状态任意组合

两者来自不同参数轨迹，不是原训练的连续状态。分别保存部署选择和续训检查点并注明用途。
