保存模型的目的不是留下一个参数文件，而是在稍后恢复所需的计算过程。推理关心函数与输入输出约定，继续训练还依赖动量、随机序列和数据进度；相同权重并不足以保证下一步相同。本章从这个区别确定应保存的状态，讨论更新边界、EMA 与数据游标，再用中断前后的单步对照建立可验证的恢复标准，承接模块注册和训练循环中的状态管理。

前置知识：训练循环与指标归约 · PyTorch 模块、参数与状态 · 梯度下降、动量与 AdamW

01推理导出与训练恢复

用于推理的文件至少要恢复模型函数：参数、持久 Buffer、结构配置和输入输出预处理。用于继续训练还要恢复优化过程：优化器状态、调度器、精度管理、训练步数、随机状态及数据进度。两种用途需要的状态不同。只载入权重再开始训练，通常是从旧参数重新启动一个优化过程，不能直接称为与未中断训练等价。

例如 Adam 的更新依赖历史一阶与二阶矩及步数修正；同一组权重配不同优化器状态，会产生不同下一步。模型中 BN 的运行统计也会影响推理函数，但不属于可训练参数。仅以参数数量一致作为完整恢复的判断依据，会遗漏这些状态。保存前先列出后续计算依赖哪些量，再决定文件内容和恢复顺序，有助于避免恢复时遗漏必要状态。

保存内容由恢复目的决定

推理需要同一函数，续训还需要同一优化过程与数据序列。权重只是共同的一部分。

检查：分别建立推理恢复清单和续训恢复清单，要求每个影响下一步的状态都有来源。

02模型状态与结构配置

首先需要恢复的是同一个模型函数，而不是一个参数形状碰巧匹配的容器。除了权重，归一化状态、结构配置和输入输出变换都会参与计算。明确这些依赖，才能判断严格加载检查覆盖了什么、又遗漏了什么。

state_dict 记录注册参数和持久 Buffer 的键值，结构代码仍要正确创建。层数、宽度、激活、Norm ε、位置编码与输出含义等配置可能改变函数，即使部分权重 shape 仍相同。strict=True 可发现键缺失或多余，但不能证明所有非 Tensor 配置匹配。strict=False 应用于明确的迁移场景，逐条解释 missing/unexpected keys，不能作为消除加载错误的一行万能设置。

预处理统计、词表、图像尺寸、相机或模态顺序、动作单位及编码规则，也应与模型版本绑定。用于推理的输出后处理同样属于函数：同一个归一化预测配另一套反标准化统计，会变成不同物理量。保存代码版本、配置摘要和数据版本，能让后续人员解释结果来自哪套约定。参数文件成功读入仅是恢复链路中的一步，不保证恢复后的计算等价。

03优化器状态与参数分组

若要继续原来的优化过程，下一步更新还必须读取相同的历史状态。动量与二阶统计关联的是具体参数对象及其分组，不能只按张量数量匹配。模型重建、参数组重建和状态加载因此需要一致的语义顺序。

优化器的状态与参数集合、参数组顺序和各组超参数有关。重建模型后，应按原策略建立参数组并载入对应状态；只让总参数数量相同，不足以保证动量被配给正确参数。若新增模块、修改冻结范围或重排分组，原优化器状态可能需要有意识地部分继承或重建，此时应明确这是一项训练策略变化，而非严格续训。

学习率调度器还有自己的计数与基准状态，构造和加载顺序应遵守所用接口，避免初始化覆盖已恢复的学习率。AMP 的 GradScaler 也可能持有动态尺度和增长计数。恢复后打印每组参数名、当前学习率、权重衰减与优化器步数，再执行一小步对照。若参数值相同但下一步不同，先检查这些状态，再归因于随机性或硬件误差。

例：同一权重，动量不同，下一步就不同

  1. 用简化动量更新 vnew=0.9v+gv_{\rm new}=0.9v+gvnew​=0.9v+g⁠，wnew=w−ηvneww_{\rm new}=w-\eta v_{\rm new}wnew​=w−ηvnew​⁠。
  2. 两次恢复具有相同 w、g=1、η=0.1，但旧 v 分别为 0 和 2。
  3. 新 v 分别为 1 与 2.8，参数位移分别为 −0.1 和 −0.28。

只恢复参数无法恢复优化器记忆，下一步等价才是续训的直接证据。

04保存时机与更新边界

训练在一轮更新内部也有多个中间状态，保存位置不同，恢复所需的信息就不同。完整更新边界通常最容易定义；中途保存则必须额外处理尚未消费的梯度和分母。先规定恢复点的含义，再选择文件写入与同步方式。

最容易解释的保存点通常是一次完整 optimizer update、调度器与必要日志状态更新之后，下一次取数据之前。若在梯度累积中间保存，除参数与优化器外，还要保存已累积梯度、累计有效分母、当前微步及精度相关状态，否则恢复后无法继续同一更新。若系统没有实现这些状态恢复，应把保存限制在完整更新边界，并清楚记录步数含义。

epoch、Batch 索引、optimizer_step 和已消费 token 数并不总成比例。最后一个短 Batch、被跳过的溢出更新、动态 Batch 与梯度累积都会造成差别。文件写入也应避免中途失败留下看似最新的半文件，可先写临时文件、验证完成再切换指向。多进程系统还要明确哪些 rank 写哪些状态、何时同步；不能让多个进程无约定地覆盖同一文件。

“第 1000 步”必须说明是哪一种步

数据读取次数、微批次、实际优化器更新与 scheduler 计数可能不同。

检查：同时记录 epoch、样本游标、micro_step、update_step 和有效元素量，并在恢复时打印核对。

05EMA 权重与训练状态分别保存

有些训练过程同时维护当前参数和用于评价的平滑参数，这两套权重代表不同状态。EMA 的递推还依赖更新频率与初始条件，不能只保存最终数值后任意接着平均。把在线优化与平均模型分别记录，才能正确比较和恢复它们。

参数的指数移动平均（EMA）维护另一套用于评估或推理的权重。记 θk\theta_kθk​ 为第 k 次实际优化器更新后的在线参数，EMA 按 θˉk=βθˉk−1+(1−β)θk\bar\theta_k=\beta\bar\theta_{k-1}+(1-\beta)\theta_kθˉk​=βθˉk−1​+(1−β)θk​ 更新，本文取 θˉ0=θ0\bar\theta_0=\theta_0θˉ0​=θ0​⁠。它平均的是模型参数，与 Adam 内部对梯度及梯度平方的移动平均不同。β\betaβ 越接近 1，旧权重保留越久；第 j 次历史更新的系数按 β\betaβ 的幂次衰减，约 11−β\frac{1}{1-\beta}1−β1​ 次 EMA 更新给出常用的时间尺度估计。EMA 是否改善验证表现需要实测，不是所有微调都应默认启用。

在线模型仍承担前向、反向与优化器更新；EMA 模型使用独立存储、关闭梯度并在 no_grad 下更新。ema=model 只是给同一对象增加名称，不能得到平均模型；浅复制 state_dict 也不是历史快照。本文约定每次成功的 optimizer update 后更新 EMA：梯度累积的中间微批次不更新，AMP 溢出导致优化器跳步时也不推进。若改为每隔若干次更新才平均，或使用随步数变化的 β\betaβ⁠，必须保存 EMA 自身计数、频率和衰减配置，不能只比较 β\betaβ 数值而忽略实际时间尺度。

参数之外还要确定 Buffer 的处理方式。整数计数器不能直接按浮点 EMA 处理；BatchNorm 的运行均值和方差可以选择复制在线统计、按约定平均，或用代表性数据重新估计，但三者得到的推理函数可能不同。本例统一复制全部 Buffer，并在 checkpoint 中保存该约定。使用 PyTorch AveragedModel 时还应注意：默认是等权平均，EMA 需要显式平均函数；avg_fn 和 multi_avg_fn 不随 state_dict 保存，恢复时必须重建相同规则。

完整续训应同时保存在线模型、EMA 模型、优化器及 EMA 规则和计数，再加上前文的调度器、随机与数据状态。不能把 EMA 权重载入在线模型，却沿用原在线模型的动量，并称为连续恢复。验证结果与推理导出应标明使用在线权重还是 EMA 权重；比较时使用相同数据和预处理。下面以无随机算子的 CPU 小模型验证两条路径，EMA 初始值和 Buffer 策略均明确，因此恢复后的连续更新可以逐项完全相等。

06随机状态与恢复顺序

恢复参数和优化器以后，下一次随机运算仍可能与未中断路径不同。seed 只指定随机序列的起点，而续训需要回到序列中的当前位置。应先识别实际使用的生成器，再按不会被模型重建消耗的顺序恢复状态。

seed 描述随机序列的起点，训练运行一段时间后，需要的是当前生成器状态。Dropout、噪声采样、数据增强与采样顺序可能分别使用 PyTorch CPU、各 GPU、Python、NumPy 或显式 Generator。恢复时只重新设置最初 seed，会从序列开头重放，通常不同于未中断训练的下一步。应按实际使用的生成器保存和恢复状态，并注意模型重建本身可能消耗随机数。

恢复随机状态也不保证跨设备、跨内核或跨版本逐比特相同。非确定性算法、浮点求和顺序和并行调度都可能带来差异。可以在声明的同环境条件下做严格数值对照，在迁移环境时使用明确容差和任务指标验证。不要把“设置 deterministic”当成所有层面的复现承诺，也不要把所有差异都归咎于随机性而忽略错误的优化器或数据状态。

07数据游标、Worker 与预取

下一批数据通常不是由主循环中的一个数字完全决定的，预取队列和 Worker 可能已经推进了各自的状态。严格续训因此还依赖数据管线的可恢复能力。将固定下一批的优化对照与真实数据流恢复分开，可以定位差异来自哪一层。

若下一批数据固定且无增强，恢复位置相对直接；实际 loader 可能已经预取多个 Batch，Worker 又各有随机增强状态。保存主循环的 Batch 编号，并不等于保存所有已预取但未消费的状态。IterableDataset 的流式游标、分布式 Sampler 的 epoch 与排序、动态长度分桶，都影响恢复后的数据序列。严格恢复需要数据管线支持，不能仅靠一个通用 checkpoint 字典自动完成。

可选策略包括在 epoch 边界恢复、使用可序列化 sampler 游标，或依据样本 ID 和明确随机规则重建下一批。每种策略都有成本与等价范围，应在文档中声明。单步恢复测试可先使用固定的下一批数据，单独验证模型与优化器状态；然后再加入真实 loader 和增强测试，将优化恢复与数据恢复分层定位，避免一次性把所有差异混在一起。

08最佳模型与最新训练状态

用于报告最好结果的模型与用于继续工作的位置，未必是同一个训练时刻。若把两种用途混在同一个“最新”文件中，容易恢复错误的权重或产生不连续的日志。保存策略应同时说明选取标准、状态内容和预期用途。

最佳验证模型用于选取某个评价指标上的权重状态，最新 checkpoint 用于尽量少丢失训练进度；两者可能来自不同步数，也可能保存不同内容。内存中保存 best_state=model.state_dict() 不会自动生成独立历史快照，需要深拷贝或立即写入文件。训练结束再保存这个浅引用，可能得到最后一轮而非最佳一轮的权重。

选取最佳模型本身还涉及验证纪律：反复尝试配置会适配验证集，最终报告应保留独立测试或明确选择过程。多个指标冲突时要事先规定选择规则，不能在评价结束后仅报告最有利的指标。文件名或元信息应包含选取指标、步数、配置与来源，使读取者知道它是推理模型、迁移初始化还是完整续训状态，避免错误恢复后继续把日志拼接成同一个实验。

例：最佳模型与最新状态可以同时存在

  1. 第 20 次更新验证最好，但训练继续到第 30 次更新后中断。
  2. 部署可使用第 20 次的最佳权重；恢复训练通常需要第 30 次的完整优化与数据状态。
  3. 若把第 20 次权重与第 30 次动量随意拼接，既不是最佳模型的原状态，也不是原训练的连续恢复。

明确文件用途能避免不一致状态被混用。

09中断前后的单步等价

恢复是否完整最终可以通过同一下一步的计算来检验，而不是仅检查文件能否加载。未中断路径与重建路径应从相同输入和随机状态出发，逐项比较输出、梯度和更新后的状态。第一个出现差异的位置，能够把恢复错误缩小到具体依赖。

建立一条未中断基线，在某个更新边界复制完整状态，继续用固定下一批数据做一步；另一条路径重建模型与优化器、载入状态后处理同一批数据。比较这一步更新前的输出与 loss、梯度、更新后的参数和优化器状态。关闭或控制随机算子，使用合适 dtype 与容差。只比较刚载入时参数相同，仍不足以证明后续优化过程恢复正确。

单步恢复示例使用小型网络与可控随机性。分布式训练、动态数据流和不同硬件可能增加额外状态，应在相应环境比较中断前后的下一步。出现不一致时按输入与预处理、模型 Buffer/模式、随机状态、优化器、调度器和数据游标顺序查找第一个分叉。保存与恢复是训练算法的一部分，应该像前向与反向一样具有可检验约定。

固定下一批的短例通过后，可运行共同训练项目的 save_training 与 main 中恢复分支：同一份变长数据、采样器和模型继续训练一整轮。序列化同时保存归一化 Buffer、AdamW 状态、按更新推进的 StepLR、CPU RNG、显式 DataLoader generator 和实际 update_step；构建新对象并加载后，再恢复随机状态。对照不仅要求参数相同，还要求样本顺序、下一轮 loss、优化器状态和调度器状态逐项相等。这个更完整的证据仍限定在当前 CPU 环境、num_workers=0、无随机增强且 epoch 边界保存；不能推断任意中途游标或跨设备恢复。

比较下一步，而非只看加载是否报错

同权重还可能配错动量、模式、随机数或下一批输入。下一步对照可直接揭示这些差异。

检查：保留基线与恢复两条路径，逐项比较 loss、grad、参数、优化器状态及实际学习率。
