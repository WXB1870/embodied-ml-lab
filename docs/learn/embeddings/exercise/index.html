推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

token ID、position_id、动作未来步 h 与生成时间 t 分别代表什么？它们可以共用一个未经解释的 time 变量吗？

参考解与分析

token ID 表示词表中的离散身份，position_id 表示模型序列中的位置；动作未来步 h 表示预测块中第几个动作。它们可能相关，但不是同一个量，例如一张图像可以展开成许多个视觉 token。

生成时间 t 表示扩散或流匹配路径上的状态，不是机器人已经经过多少秒，也不是动作索引。应分别命名并记录范围、单位、形状和注入位置，否则即使张量维度兼容，也可能输入了错误条件。

代码对应：追踪 Embedding 的整数索引、RoPE 位置与 time_mlp 输入三条不同路径。

  • 至少正确区分离散身份、序列位置与生成状态。
  • 说明维度相同不能证明语义相同。

为什么 RoPE 的旋转保持范数，同时还能让 Q/K 点积包含相对位置？共同平移两组位置时如何检查？

参考解与分析

每个通道对乘以二维正交旋转矩阵，因此其欧氏范数不变。两个向量分别旋转后做点积，组合旋转由两个位置的角度差决定，所以点积可以包含相对位置关系。

固定原始 Q/K，分别在位置 m、n 计算点积，再同时将两个位置加上同一偏移，结果应在浮点容差内一致。这个检查还要求使用相同频率与通道配对约定，不能只验证每个向量的范数。

代码对应：比较 rope(q,pos)@rope(k,pos).transpose(-1,-2) 与共同加偏移后的矩阵。

  • 解释正交性与相对角度。
  • 提出同时平移位置的点积对照检查。

给每个 token 加上不同位置编码后立刻平均池化，是否已经保存了内容的顺序？

参考解与分析

没有保证。若编码仅为 xi+pix_i+p_ixi​+pi​⁠，均值只剩内容均值与位置均值，交换内容但固定位置集合不会改变结果。对 [1,3]、[3,1] 和位置 [0,10]，两者的均值都为 7。

内容必须先与位置发生交互，配对关系才可能进入聚合结果。例如 ∑ixipi\sum_i x_i p_i∑i​xi​pi​ 在两例中分别为 30 和 10。这个乘积只是展示机制，实际可由合适的非线性或注意力形成，不保证任意编码器都学会保留所需信息。

如果进入池化前的骨干早已编码空间关系，池化仍可能保留任务所需信息。因此应分析整个计算路径，不能仅由最后一个 mean 判定模型完全丢失空间能力。

代码对应：固定位置编码，交换内容，比较交互前后两种聚合。

  • 展开均值公式给出反例。
  • 区分“注入位置”与“保留内容—位置关系”。

参考实现与说明
参考实现
import math def rotate_pair(pair, position, frequency):    if len(pair) != 2:        raise ValueError("每个旋转平面需要两个通道")    a, b = pair    angle = position * frequency    c, s = math.cos(angle), math.sin(angle)    return [a*c-b*s, a*s+b*c]

每个通道对执行相同形式的旋转；完整 RoPE 只是增加多个频率和批量维度。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

换 tokenizer 后沿用原 Embedding 行号

相同词表大小不能证明 ID 意义相同。保存并核对词表、特殊 token 和文本模板，打印固定文本的编码结果。

将 padding_idx 当作完整 Padding 处理

位置向量、偏置和后续交互仍可能产生非零值。有效位需要沿注意力、池化和损失继续使用。

缓存解码把 position_ids 重置为零

历史 K 已有位置，新 Q 的偏移若错误，点积关系就变。用整段与不等长分块输出逐位置对照。

频率编码可计算就意味着可可靠外推

数学上能得到远处位置的向量不代表模型在该分布上训练过。长上下文或时间尺度改变都需要相应验证。

把生成时间当机器人执行步

一次 ODE/去噪步更新整个动作块，H 轴与生成时间轴并非同一个轴。写清单位和 shape，分别做输入干预。
