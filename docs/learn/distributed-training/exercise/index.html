为什么 4 张卡上的 DDP 不等于拥有一张 4 倍显存的卡？

参考解与分析

数据并行复制模型，各进程处理不同数据并同步梯度；默认没有把权重和优化器状态拆成四份。因此单张卡仍需装得下自己的完整模型状态与局部激活。

演示每个 worker 都创建独立 Linear 和 optimizer，DDP 包装后只是同步训练。若模型本身放不下，需要考虑降低状态或激活开销，或进一步学习 FSDP、ZeRO，而不是只增加 DDP world_size。

代码对应：worker 内模型、优化器与 DDP 的初始化。

  • 能区分数据分片与模型状态分片。
  • 能指出 DDP 对本地容量和全局 Batch 的不同影响。

各 rank 的有效动作数不同，怎样让梯度和日志都对应全局平均？

参考解与分析

梯度采用本地误差 sum 乘 R/N，再由标准 DDP 平均；N 是所有 rank 的有效计数之和。局部 mean 需要额外按有效数量加权，不能直接等权平均。

日志归约误差总和与计数，再相除。所有 rank 共同参加归约；零有效 rank 也需保持同步，评估还要核查 sampler 补齐造成的重复。PyTorch 练习仅验证这个数学关系，实际 Gloo 演示仍受交付环境通信限制。

代码对应：ddp_scaled_local_loss；演示 stats 的 all_reduce 与全局分母。

  • 能推导 R/N 的来由。
  • 能分别写出梯度和日志的正确汇聚方式。
  • 能说明数学模拟与分布式运行验证的边界。

求局部 mean 在 DDP 下应使用的权重

counts[r] 是 rank r 的有效元素数。实现 ddp_mean_weights(counts)，返回每个局部 mean 应乘的权重，使随后按 rank 平均得到全局有效元素平均。counts 为非空非负整数列表，总数必须大于零；零计数 rank 的权重为零。本题只是标准库数学练习，不启动分布式进程。

参考实现与说明

参考实现
def ddp_mean_weights(counts):    if not counts or any(not isinstance(n, int) or n < 0 for n in counts):        raise ValueError('有效计数不合法')    total = sum(counts)    if total == 0:        raise ValueError('全局没有有效元素')    world_size = len(counts)    return [world_size * n / total for n in counts]

数学权重为零只说明该 rank 不贡献监督，不表示可以跳过同步。真实代码宜使用保持计算图的局部 sum，再乘 R/N；这样避免零计数 rank 先计算不存在的 mean。全局分母需通过真实通信或已知窗口计数获得。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

每个 rank 都读取完整数据却当作不同分片

DDP 不替代 sampler。记录各 rank 样本 ID，检查预期覆盖、重复和尾部策略。

平均各 rank 的 mean 就当全局均值

当有效数不同，这会赋予进程相同权重。归约分子和分母，并对训练梯度使用相匹配的缩放。

某 rank 发现空监督就自行 continue

会破坏其他进程的同步顺序。先协调全局有效计数，保持所有 rank 的通信协议一致。

双进程无法启动却把单进程检查写成已通过 DDP

真实通信、初始化与同步没有被验证。应明确标注环境阻塞，在可用环境重新运行真实进程测试。
