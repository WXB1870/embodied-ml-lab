为什么冻结了大部分参数，训练仍可能占很多显存？

参考解与分析

权重本身仍然存在，输入、激活和算子临时内存也没有自动消失。若冻结层上游还有可训练 Adapter，梯度必须穿过冻结层，相关前向信息可能仍要保存。

显存估算把总参数 P 和训练参数 Pₜ 分开；CPU hook 另外观察反向保存量。应先分清参数状态和激活哪个主导，再选择冻结、减序列、减微批次或重计算。

代码对应：adam_state_bytes 的 4P4P4P 与 12Pt12P_t12Pt​⁠；演示 saved_tensors_hooks。

  • 能写出参数状态估算的假设与遗漏项。
  • 能解释冻结权重但保留输入梯度的情况。

如何证明 checkpoint 既节省保存量，又没有悄悄改变训练？

参考解与分析

先固定参数、输入和随机状态，比较普通前向与 checkpoint 的输出及每个训练参数的梯度。再在实际设备上测峰值分配和运行时间，而不是只看到程序能运行。

演示的逻辑保存量说明机制，练习进一步加入 Dropout 和不带梯度的输入，覆盖重算一致性与非重入语义。带全局副作用或可变状态的模块仍需额外审查，因为重算可能不再等价。

代码对应：run(False/True) 与 checkpointed_forward 的梯度、Dropout 和保存量断言。

  • 能区分正确性验证和硬件收益测量。
  • 能说出至少一种导致重算不一致的状态变化。

估算 FP32 Adam 的参数状态内存

实现 adam_state_bytes(total_params, trainable_params)。两个输入都是非负整数，且训练参数量不大于总量。按 FP32 权重、FP32 梯度、两个 FP32 Adam 矩估计，返回 weights、gradients、moments、total 四个字节数。状态已初始化，不计激活、缓存或临时工作区。非法输入抛 ValueError。

参考实现与说明

核对思路后，试着收起答案、恢复题目并独立重写；通过测试只表示满足本题提供的检查。

参考实现
def adam_state_bytes(total_params, trainable_params):    if (not isinstance(total_params, int) or not isinstance(trainable_params, int)            or total_params < 0 or trainable_params < 0 or trainable_params > total_params):        raise ValueError('参数数量不合法')    weights = 4 * total_params    gradients = 4 * trainable_params    moments = 8 * trainable_params    return dict(weights=weights, gradients=gradients, moments=moments,                total=weights + gradients + moments)

本题是注明假设的状态内存账单。全量 FP32 Adam 的这个简化部分是每参数 16 字节，但真实峰值还取决于激活、优化器实现和工作区；不能用计算结果判断一个真实模型一定能装进某张卡。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

模型文件大小乘固定倍数就断言显存够用

状态 dtype、激活、工作区和通信都会改变峰值。列出内存构成并测完整训练步。

每步 empty_cache 解决 OOM

它不能释放活跃张量，也可能降低性能。先定位对象生命周期和实际最大分配。

重计算区段包含不可重复副作用

重算会再次执行函数，可能改变状态和梯度。检查随机性、buffer 更新与外部缓存，做等价对照。

把 saved_tensors_hooks 总字节当显卡峰值

统计口径不同，可能重复计算共享存储且遗漏工作区。标明逻辑保存量，并在 GPU 上独立测峰值。
