推导与分析

先写出推导、计算或反例，再展开参考解核对假设与关键步骤。编程题位于下方，可从本页目录直接进入。

动作 MSE 降低，但闭环成功率下降。你会怎样区分目标函数、数据和执行的问题？

参考解与分析

先按任务阶段、动作维度和指令分组查看离线误差，再回放输入与标签时间戳。若相同条件有多个有效动作模式，均值回归可能降低误差却产生不可行的中间动作；若时间错位或单位错误，优化器可能只是在更精确地拟合错误监督。

随后固定模型、控制器和初始条件运行闭环，比较模型输出、执行器接受的参考和实测状态。若失败只发生在偏离示教后的新观测，重点检查分布偏移与恢复数据；若意图正确而跟踪错误，则应检查执行接口。不能仅凭损失下降把问题归为模型容量不足。

代码对应：code.source 的监督 loss 与 rollout 循环；masked_bc_loss 的有效元素归约。

  • 至少提出三个可区分的原因。
  • 每个原因对应一个可观测检查，而不是只建议调参。

同一个 Batch 同时存在尾部 Padding 和未使用的动作维度，怎样扩展损失才不会改变有效样本的权重？

参考解与分析

将时间有效性 [B,H] 与动作维度有效性 [D] 或 [B,D] 组合成 [B,H,D] 掩码。只把有效元素纳入分子，并按同一集合的元素数归一化；若使用任务或维度权重，分母也要遵循已明确的加权统计定义。

加入三组对照：修改无效位置的有限数值时损失不变；有效位置的梯度存在、无效位置的梯度为零；全无效 Batch 明确报错或被外层跳过。对 NaN 必须另做检查，不能以为 Mask 的零可以消除它。

代码对应：pytorchTask：mask.expand_as(pred)、count 与 loss.backward()。

  • 能写出联合 Mask 的形状。
  • 说明分子分母一致及全无效边界。

左右两种示教使 MSE 预测为零。加入历史、改成生成模型、扩大网络，分别改变什么？

参考解与分析

历史只有包含能区分左右的可用信息时才缩小条件方差；若历史仍完全相同，最优条件均值不会改变。增加输入后的总体风险分解，不能直接保证有限数据上的泛化改善。

生成模型可以保留两个有效模式；它不能知道输入中没有提供的任务意图。扩大确定性 MSE 网络提高函数拟合能力，却没有把损失的总体最优解从条件均值改为某个模式。

代码对应：在 ±1 合成标签上分别加入方向条件与独立随机条件，比较总体最优风险。

  • 区分信息、输出分布与函数容量。
  • 利用风险分解说明何时最小 MSE 能下降。

参考实现与说明
参考实现
def mse_optimum(actions):    if not actions:        raise ValueError('actions must be nonempty')    mean = sum(actions) / len(actions)    loss = sum((a - mean) ** 2 for a in actions) / len(actions)    return mean, loss

[-1, +1] 得到的 0 不是一条示教。损失最优与任务可执行是两个判断；真实数据中应先检查同一条件是否确实存在多种合理动作。

辨析与纠错

判断下面的说法或实现会在哪一步失效，并说明成立所需的条件，再展开分析核对。

动作与状态只凭同一个索引配对

采集、发送、接纳与实测时间可能不同。以日志时间戳和数据规范确定标签相对观测的方向，并检查接触与延迟片段。

用更深 MLP 解决条件均值问题

容量增加不改变平方误差的总体最优统计量。先检查相同条件下标签是否多峰，再决定增加条件或学习分布。

把 Padding 的零也当成停住动作

零是合法动作值，不能代表缺失监督。显式保存 Mask，并分别验证有效分母和输入可见性。

把训练集小误差当闭环证据

离线样本分布由专家生成，在线状态由策略自己生成。保留恢复场景、完整 rollout 和失败归因，检查访问分布差异。

调整动作维数后沿用原学习率解释

sum 与 mean 的轴会改变梯度尺度。先统一有效元素归约，再比较优化器和模型结构。
