分词器（Tokenizer）把文本转换为离散 Token ID；自回归模型则按顺序，用已有前缀预测下一个 Token 的条件分布。训练使用真实前缀并行计算各位置的损失，生成时把刚得到的 Token 接回前缀继续预测。二者共同定义从文本到序列概率的接口。本章先认识这个流程，再精确对齐输入、标签、可见性与有效监督。

前置知识：概率、统计与训练目标 · Transformer：注意力、残差与序列建模 · Embedding 与位置编码

本章学习目标

  • 区分分词、Embedding、Attention Mask 和 Loss Mask。
  • 构造 prompt 与回答的错位监督，保留真实 EOS。
  • 检验标签只移位一次，并按有效目标 token 归约。

01分词与离散接口

分词是将文本按词表与规则转换为 Token 序列的过程，Tokenizer 还负责特殊标记和反向解码。一个 Token 不必对应一个字或一个词。词表与切分规则共同构成模型的离散输入接口。

Tokenizer 将文本转换为词表中的整数序列，可能使用 BPE、WordPiece、Unigram 或字节级规则。一个汉字、单词或数字不一定只占一个 token；空格、标点、大小写和特殊模板也会影响切分。训练与推理必须使用匹配的词表和配置，不能因为输入最终都是整数就任意替换。示例中的人工词表仅用于展示标签对齐，不代表真实模型的分词方法。

特殊 token 定义序列起始、结束、填充或角色边界，聊天模板可能自动插入它们。手工再次添加 BOS/EOS 会造成重复，省略必要边界又可能改变生成任务。扩充词表时还要调整输入嵌入和输出词表维度，并处理新权重初始化。先打印 token 字符串、ID、有效位和标签，再进入神经网络，是定位监督问题最便宜的一步。

保存 tokenizer 与模板，别只保存模型权重

同一个 ID 的含义取决于词表，角色边界与特殊 token 又影响模型看到的条件。

检查：对固定输入记录完整编码结果，包括特殊 token，验证训练/推理和重新加载后一致。

02自回归概率分解

自回归模型把序列的联合概率分解为各位置在已有前缀下的条件概率乘积。它规定生成的依赖顺序，不等于某一种网络层。下面将这个分解连接到下一 Token 预测与逐位置交叉熵。

Teacher Forcing 使用真实前缀进行并行训练，依靠因果 Mask 保证每个输出只读合法历史。推理时前缀包含模型自己生成的 token，因此训练分布与自由生成状态可能不同，这并不使训练公式无效，但提醒我们不能仅用 teacher-forced loss 代替生成评价。输出参数化也应区分：离散动作 token 可以采用类似目标，连续动作的回归或 Flow Matching 则使用不同损失。

03logits 位置与标签移位

标签移位是让一个输入位置的输出对应到它应预测的下一个 Token。它建立 Logit 行与目标 ID 的对应，不改变输入可见性规则。下面用短序列明确谁负责移位，避免漏移或重复移动。

若输入为 [BOS,A,B,EOS]，位置 0 的隐藏状态看到 BOS，监督目标应是 A；位置 1 看到 BOS,A，监督 B；位置 2 监督 EOS。常见自写 Loss 使用 logits[:,:-1] 对 labels[:,1:]。某些库的 CausalLM 在内部已经完成这一移位，通常传同长 labels；外部再移位会跳过一个 token。必须读取具体模型与损失接口，不能把某个仓库的调用方式当成所有模型的默认。

未移位时，当前位置可能直接看到被要求预测的 token，训练变成复制输入，损失很低却不会正确生成。移位两次时，模型可能被要求从不完整前缀预测隔一个位置的目标，任务同样改变。避免只检查 flatten 后的元素数：它可以完全对齐却在语义上错位。用几个可读 token 手工列出“输入前缀→目标”，再把这些行对应到 Tensor 索引。

例：BOS、A、B、EOS 的三条监督

  1. 输入位置 0：BOS → 目标 A。
  2. 输入位置 1：BOS,A → 目标 B；输入位置 2：BOS,A,B → 目标 EOS。
  3. 最后位置的 logits 没有本序列内下一 token 标签，按本例约定不计入损失。

移位关系来自每个位置看到的前缀，不来自张量恰好能 reshape。

外部移位加内部移位会错两次

模型可能已经在 forward/loss 内切片。多移一次并不会更因果，而是改变预测目标。

检查：查看具体 CausalLM 源码或文档，打印参与损失的 logits 位置与目标 token，逐项手算。

04Prompt、回答与 EOS

Prompt 是已给定的条件文本，回答是需要模型生成的目标部分，EOS 是标记序列结束的特殊 Token。它们决定输入、监督与停止规则。先确定每个目标属于哪个区域，再设置损失有效位。

条件生成经常只监督回答区，把 Prompt 标签设为 ignore_index，同时仍让回答位置读取 Prompt。关键是按目标 token 的所属区域决定是否监督，之后再应用移位。第一个回答 token 通常由最后一个 Prompt 位置的 logits 预测，如果按 logits 的当前位置直接屏蔽全部 Prompt，可能连这条重要监督也一起删掉。边界处尤其需要逐位置表格。

EOS 是模型学习何时停止的重要目标；如果一直被屏蔽，模型可能不会在正确时刻结束。PAD 与 EOS 在某些配置中可以共享 ID，这时不能仅靠 input_ids==pad_id 推断无效位置，否则真正的 EOS 也会被忽略。有效长度或 attention_mask 应来自样本结构，并与 labels 的屏蔽策略一起检查。文本截断若切掉回答或 EOS，也会改变有效目标数量。

例：第一个回答由哪个位置预测

  1. 完整序列为 [BOS,提示,回答1,回答2,EOS]，只监督回答与 EOS。
  2. 同长 labels 可写为 [忽略,忽略,回答1,回答2,EOS]；移位后 logits 的位置 1 监督 回答1。
  3. 如果先把所有 Prompt 位置的 logits 删除，再移位，就可能漏掉第一个回答目标。

Loss Mask 以目标归属定义，再与预测位置正确错位配对。

05Attention Mask 与 Loss Mask

Attention Mask 选择某个预测能读取的输入，Loss Mask 选择哪些目标计入训练代价。忽略一个标签不等于移除其输入表示。二者应由信息边界与监督范围分别定义。

Attention Mask 控制输出能读取哪些输入，ignore_index 控制某个目标是否贡献损失。将某位置 label 设为 −100，并不阻止该 token 的隐藏状态影响其他位置；Prompt 不受直接监督，也可经回答 Loss 的反向路径收到梯度。另一方面，屏蔽 Padding Key 不会自动移除 Padding Query 的损失，需要对 targets 单独处理。两种 Mask 要沿信息与监督两条路径分别推导。

若把多条样本打包进一条长序列，还要处理样本间的边界：让后一条读取前一条是否属于设计、位置是否重置、EOS 后哪些目标有效，都需要明确。只在拼接处放一个 EOS 不会自动创建 block-diagonal Attention Mask。错误打包可能让模型利用另一条样本的内容，改变训练条件分布。高效训练技巧不能绕过每个预测目标实际看到了什么这一基本问题。

06交叉熵的轴、归约与空监督

序列交叉熵对每个有效目标取预测类别的负对数概率，再按选定分母归约。类别轴是词表，位置轴是序列，两者承担不同角色。先对齐类别和目标，再明确空监督时的处理。

PyTorch 交叉熵的类别维度接口需要核对。对 [B,T,V] logits，可展平成 [B·T,V] 与 [B·T] targets，或按接口转置到相应布局；不要把 T 当作类别数。使用整数类别标签时，ignore_index 排除相应目标；reduction=none 便于显式统计有效 token，再按真正的有效数归约。若采用类权重等选项，默认 mean 的分母还有相应约定，不能套用无权重公式。

全批没有有效目标时，平均损失无定义，不应通过任意小 ε\varepsilonε 静默得到零再继续优化；可以按训练协议拒绝或跳过，并记录原因。变长回答按所有 token 等权与先按样本平均再等权是不同目标，日志也应说明口径。perplexity 由所定义的平均负对数似然指数得到，跨不同 tokenizer、数据切分或监督区间直接比较通常没有同一单位。

Padding 后的序列长度不是有效 token 数

Prompt、Padding、截断和忽略标签共同决定分母。错误平均会改变梯度和指标。

检查：使用不同回答长度与全忽略边界，显式核对 targets!=-100 的数量，并手算少数 token 的平均损失。

07Teacher Forcing 与逐步生成

Teacher Forcing 在训练中提供真实前缀，逐步生成则使用模型此前输出构造后续前缀。采样规则决定怎样从预测分布选一个 Token，KV Cache 决定怎样复用历史计算。它们都不改变标签原本的对齐关系。

训练一次计算所有前缀的预测，推理则先处理已知 Prompt，再选择一个 token 接入前缀，继续预测。贪心、采样、温度和截断候选策略作用于 logits 到 token 的选择，不改变训练时标签应该如何移位。KV Cache 复用历史 K/V 以减少重复计算，但位置偏移、Attention Mask 和有效长度仍须与完整前向一致。缓存错误可能只在第二次或分块生成时显现。

自由生成评价应检查内容、格式、停止条件和长度，不只是 teacher-forced loss。多模态模型还要保证图像占位 token 与视觉特征注入位置对齐，结构化输出要核对分隔符和数值编码规则。若训练输出很流畅却不遵循条件，先检查 Prompt 是否被正确输入、回答监督是否包含边界、以及数据中条件与答案是否有足够变化，避免只靠更低学习率修补接口错误。

08短序列中的逐项对齐

完整模型容易掩盖一个位置的偏移，短序列却可以逐项手算。将已知答案写成可控 logits，再覆盖回答边界、结束符号和 Padding，可以先验证监督问题本身，再判断网络是否学会它。

构造两条不同长度的短序列，明确 BOS、Prompt、回答和 EOS，画出每个 logits 所预测的目标，再运行自写 Loss 与官方损失的对照。人工令正确目标 logits 很大，损失应接近零；令高分给前一个或后一个 token，损失应显著增加。测试应覆盖第一个回答、最后 EOS 与 Padding，不能只用没有边界的长随机序列。

示例代码使用一个小型因果 Transformer，明确只移位一次，并断言五个有效目标；它验证的是监督构造与计算图。换成真实 tokenizer 后，应重新运行同样的可读探针，打印 decode 结果与有效目标区间。训练曲线异常低时尤其要检查目标泄漏与未移位，异常高时检查重复移位、词表/模板不匹配和空监督。先证明在学正确问题，再讨论模型容量。

自回归生成始于同一份离散接口与概率分解：文本被分成 Token，每个输出预测下一项，合法前缀定义条件，目标有效位定义监督。训练和生成访问的前缀不同，但每个位置预测谁应始终一致。
